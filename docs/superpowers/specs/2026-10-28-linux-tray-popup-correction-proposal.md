# Linux tray popup correction — 2026-10-28

**Status: user-approved original correction; controller Rulings 28–30 applied; Fedora native gate passed; independent implementation review pending.**

The original ownerless `Window.Type.POPUP` dialog failed repeated keyboard focus on pinned JBR b635.75/Openbox. A managed ownerless `JDialog` of `Window.Type.UTILITY` restores the window-manager path, and the user approved bounded native assistance for only that popup's own peer. It remains one transient undecorated dialog containing the shared `JPopupMenu`; no permanent Java owner frame is created.

EDT creates/packs the dialog and obtains its own XID through public JNA `Native.getWindowID`. The existing owned XCB worker preserves state atoms and adds `_NET_WM_STATE_SKIP_TASKBAR` / `_NET_WM_STATE_SKIP_PAGER`, confirming a bounded reply barrier before EDT show. Keep the peer alive through every admitted native operation or confirmed connection termination, including cancellation: otherwise its XID could be reused. Invalidation immediately drops show/actions; EDT never waits, and only one peer plus one latest request may be pending.

Ruling 26 carries the selected native root extent to verify single-device public AWT coordinate mapping. Pointer position is sampled on EDT at actual display time after preparation; moved-pointer and keyboard requests use the mapped icon anchor. Ambiguous multi-device identity declines the menu. Physical mixed-monitor acceptance remains pending.

Ruling 28 captures the actual matching Button3 press or initiating KeyPress timestamp, preserving unsigned32 bits and retiring captured press state with admission. Own-popup `_NET_WM_USER_TIME` was overwritten by JBR on map; Ruling 29's standard redirected-time experiment retained the correct value on the owned icon, but Openbox lacked `_NET_WM_USER_TIME_WINDOW` support. These failed metadata paths were removed from the implementation.

Ruling 30 supersedes the hints-only restriction. After map, send at most one advertised, standard WM-mediated `_NET_ACTIVE_WINDOW` ClientMessage to the selected root for this user-requested popup: event window = popup XID, mask = SubstructureNotify|SubstructureRedirect, words = `[1, actualPressTime, 0, 0, 0]`. Source1 identifies the application; no other active window is claimed. The same connection/host/icon/popup/admission identity and live-peer lease guard completion. Recheck cancellation after capability discovery and before sending; zero/invalid/canceled requests do not activate. The WM may refuse: no retries or focus fight. This follows [EWMH root messages and section3.8](https://specifications.freedesktop.org/wm/latest/ar01s03.html), with genuine input time as described in [sections5.15–5.16](https://specifications.freedesktop.org/wm/latest/ar01s05.html).

No direct XSetInputFocus, input grab, pager source, active-window property write, private AWT timestamp mutation, shared JBR-window write, or extra native helper/library is introduced. A two-second focus deadline disposes a denied menu. Retirement hides the still-live focused peer, waits for acknowledged focus loss or a one-second fallback, then disposes; cancel both bounded deadlines and remove all owned listeners/menu path. New requests coalesce while retirement completes.

Fedora44 aarch64/JBR b635.75 gates pass LXDE/Openbox and XFCE/xfwm4 at JBR scales1/2: all four actions, vetoed Quit reopen, Menu/Shift-F10, traversal, Escape/outside/focus loss, twenty additional reopen cycles, moved pointer, four edge placements, host loss and queued close. Actual taskbar/pager framebuffer strips remain identical. Final displayable/focused/active window and focus-owner counts are zero, with only the process LAF listener baseline. At most one disposed raw AWT inventory entry survives bounded GC after35 opens; this is an inventory limitation, not an exact raw-count baseline or live popup ownership claim. Native JVMs exit naturally. x86_64/package and physical mixed-monitor proof remain later gates.
