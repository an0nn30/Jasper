## Approved constrained-scale correction

The first frozen gate passed but fresh construction at font32 with automatic UI scale2.5 exposed additional visual failures. It remains historical passing test evidence, not usability acceptance. Prior transition-only checks started at13 and missed the fixed initial divider failure; explicit UI scale1 captures are separate inputs.

`SurfacePanel.NativeSplit` negotiates automatic leading width from the normal preference, existing resize share, actual insets/divider and measured receiving minimum. When both minima fit, it honors them. When they cannot fit, the receiving content keeps its measured minimum while the leading side retains a measured generic lane; below two generic lanes, bounded proportional allocation prevents negative dimensions without claiming useful page acceptance. Explicit divider movement ends automatic negotiation and retains Swing drag/resize behavior across refresh. The owner keeps child/UI lifetime.

Tables expose an ordinary minimum width using actual row padding, optional checkbox and first-cell icon/gap, current weighted-column math and a bounded four-glyph text allowance. Existing numeric/text minima, preferred widths, literal values and row painting remain. Font, row, column and scale changes invalidate measurement, including unchanged exact font overrides with changing icon geometry. The chooser consumes this measured receiving minimum; it does not have a filename or page-ID sizing branch.

A retained shared sidecar keeps the chooser preview at its normal preferred width when the receiver can fit it and a usable main lane. Otherwise it stacks after the listing. The existing outer vertical scroll minimum includes actual listing rows and preview header/text lines/scrollbar. Preview toggle, selection, documents and existing inner scrolling remain. No child is recreated to cross a threshold.

All form kinds now use the existing bounded short-height body/footer viewport allocation and owned focus reveal. Ordinary native ThemeDialogs can be resized to400×300, so a zero body viewport is not dismissed as a fixture-only case. Shared FormRows keep the normal fixed label grid; below a measured usable control lane they stack label/caption, retained control and visible trailing control. Height measurement uses its passed width, including trailing allocation, rather than stale bounds. Label association, focus order, IDs and invisible trailing semantics remain.

Three native font consumers previously scaled already-effective configured point sizes a second time: chooser preview, NotificationStyle and PluginDetails. They use the context-aware `NativeControlStyles.font` overload delegating the existing `SwingTypography.effective` policy. The PluginDetails correction is a specifically approved third-consumer deviation, with no other Plugins composition change. A module-owned `observeTypography` subscription reuses KitView's supported default-font property provenance and relevant UIScale events. Registration does not call a partially built owner; delivery is on the EDT, close is idempotent and queued delivery after close is suppressed. Chooser, Errors, NotificationCard, HistoryPanel and PluginDetails register only after construction and close the signal with their owner. ThemeBinding equality/publication stays unchanged.

Costs include broader minimum negotiation, retained splitter intent, constrained form stacking, font/scale callback ordering and disposal. Fresh automatic-scale and explicit-scale owner checks, actual scroll reachability, named text ink, ordinary table/numeric/icon/selection variants, normal/HERO/attached holdouts, same-theme font/family transitions and subscription teardown cover these paths. Settled chooser evidence disables animation through its existing fixture KitContext and records this policy; the earlier off-looking checked switch was captured before its Swing animation timer could advance, not a production state defect.
