## Explicit native sheet presentation

Extend DialogSpec additively with an explicit CENTERED/ATTACHED_SHEET presentation value. Retain the existing three-argument JVM constructor and centered behavior. Attached requires modal=true and a resolvable live checked owner at show; no inference from FormKind/title. Keep native owned DOCUMENT_MODAL JDialog, use host-managed undecorated attached presentation, retain accessible title and actual native parent controls. Shared FormKind.SHEET paints the body silhouette and actions. No counterfeit traffic lights or raw Swing SDK handles.

Attachment follows actual owner body boundary in screen coordinates, horizontally centered and constrained to owner/usable screen. Re-measure wrapped content after width constraint; follow parent move/resize, display/scale and content/font changes through one coalesced host controller, not competing DialogFit. Ordinary dialogs retain DialogFit. Anchors resolve their native host body boundary, not control Y. Terminal body-boundary registration is app/platform owned, preserving package DAGs; do not import workspace into windows or guess child indices. Extreme short-screen fallback screen-fits the same owned dialog so fixed actions stay reachable, with explicit native evidence and restoration when space permits.

Use a scoped theme SURFACE_SCRIM layer on the owner body, with nested/reference-counted cleanup. Modality supplies exclusion; no overlay input dispatcher, disabling anchor, or global Escape interception. Install cleanup before modal show/reentry and rollback failed attachment. Preserve popup-first Escape, nested chooser ownership, once-only disposal, drafts/secrets, and focus handoff to the pending picker; no unconditional focus restore after replacement child.

Opt in Vault-private EntryPresenter forms (Login/path-key/Note add-edit, stored-key rename, Delete, generator, change-password) and the functional New Credential selector. Keep Create/standalone Unlock centered and manager Unlock inline. Legacy unanchored Picker/Grant/KeyImport remain existing presentation unless separately justified; content modernization does not silently change ownership.

## Concrete body-boundary and ownership wiring

Use a concrete JDK/Swing-only `dev.jasper.app.platform.WindowBody` root-bound registration: a coordinate component plus a supplier of its current measured local body rectangle, with a closeable identity lease on the `JRootPane`. No global map, windows-to-workspace dependency, guessed child indices, fixed title-height subtraction or new interface. Reads require current lease identity and exact root ancestry; return defensive copies, treat empty/unlaid-out geometry as unavailable, and prevent an old lease from clearing its replacement. Replacing root content or moving the coordinate component to another root invalidates it. Native shown/expected-owner validation remains separate from geometry and plugin authorization.

Terminal `WindowContent` names its existing body component and measures its bounds plus the visible laid-out status footer in content coordinates, excluding the actual header. Register in the existing production `installTitleBar` path after chrome wiring and release before teardown. Support normal native/custom header, late FlatLaf header reparenting and fresh compact-mode construction. Compact mode is construction-only, not a new live toggle. Geometry invalidation must notice header/status changes even at unchanged outer size.

Auxiliary shells register the stable `surface.holder()` through a common production chrome/layout helper; title accessory and fallback toolbar stay outside the holder. Ordinary dialogs and attached sheets also register their own roots for immediate nested ownership. Overlay shares the terminal root and must not replace its registration. Explicitly resolve its terminal owner while retaining overlay closure authority, or reject unsupported attached routes. A popover without a supported registration cannot fall back to arbitrary root bounds.

Carry distinct stable body/title mount tokens with their actual `AuxiliarySurface`. `HostedAnchor` preserves shown/lifetime, exact token, eligible control, ancestry and host checks for either slot. After authentication pass its actual owner surface to `AuxiliaryWindows`, validating the open roster, rather than relying on holder-only descendant scans that miss title controls. Mirror this separation in fake host anchor validity and recursive parent closure. Existing Button/PICKER anchor eligibility remains; MenuButton is not silently added.

Native attachment converts measured root coordinates to screen coordinates once, using Java user units throughout. Do not multiply Retina transforms. Only the kit available-height boundary converts to its documented logical units. Constrained width must reach real Form layout before reading wrapped height. Owner/native/component/header/display/content changes coalesce through one scoped controller; queued callbacks recheck generation, registration, owner and surface liveness. Ordinary DialogFit never competes with attachment. Title updates preserve user/restored outer bounds and stable mounted controls.

Install cleanup/native-map ownership before modal reentry; revalidate owner before allocation and after shell factory returns. Handle close during construction, failed show and late registration without leaked scrim/listeners/native map or stale shown state. Use bounded idempotent resource cleanup rather than a new lifecycle framework. Body scrims use one effective theme alpha per root with nested reference counts, preserve existing layers and do not reparent controls. Selector-to-editor replacement opens from the original live owner; nested Browse uses the immediate editor.
