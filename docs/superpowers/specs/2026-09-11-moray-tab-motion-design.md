Default row height is 38 logical pixels. A View → Tab height… numeric control offers 28–72px, applies to the current window immediately after acceptance, and can restore 38. Cancellation preserves the old value. This is a session-only appearance control like toolbar visibility; persistence remains Plan 4 unless user steering changes scope. Both WindowTabs and MacTitleBar use this same value, including native JBR title height/minimum geometry. Theme changes preserve it. Other chrome dimensions remain unchanged. New windows initially use 38. Validation rejects out-of-range input. Real native controls and hit testing are retained.

Use a single EDT Swing timer per tab strip, roughly 16ms cadence, running only while visible animation is active. New tabs expand into position and subtly settle; the selected underline slides between tabs. Duration 180ms with slow-fast-slow eased movement and a subtle overshoot (bounded, no repeated oscillation). Share the same curve. Selection/model/focus and shell launch change immediately; only presentation is interpolated. Retarget rapid changes from current painted position, keep newly added controls real/clickable, and never restart an animation on shell-title updates. New tab reveal must work with overflow; hidden destinations may settle directly if movement cannot be shown. Resize/reorder/removal must never leave stale underline coordinates or missing controls. Stop timer on completion, detach and disposal; no idle timer. Retain theme/active colors. First layout settles without startup animation. Test advancement with explicit elapsed time rather than sleeps or a fabricated GUI. No changes to terminal renderer.

The existing ActionId/KeyBindings/WindowContent engine remains authoritative. Cmd+1–9 on macOS and Ctrl+1–9 elsewhere select the corresponding existing tab (missing tab: no action). Cmd+{ / Cmd+} on Mac and Ctrl+{ / Ctrl+} elsewhere select previous/next, wrapping as existing behavior. Braces are normalized to Shift+[ / Shift+] in parsing, including overrides. Do not change cmd semantics for unrelated non-Mac terminal commands: retain Ctrl+Shift and existing collision handling there. ## Close animation amendment

The user requested the same motion in reverse on close. Visible tabs contract to zero using the shared 180ms easing; following tabs move into the released space and the underline eases toward the newly selected tab's final position. Selection, shell closure and removal from the live tab model happen immediately. Only a disabled, non-interactive departing entry remains briefly for painting; it is removed at the end. Closing during entry starts from the current width. Consecutive closes retain their own deadlines; metadata refresh does not restart them.

Reorder, hiding, disposal, insufficient space or a changed viewport discard departing visuals and settle to valid geometry. Offscreen/overflow closes may settle directly. Closing the final tab does not delay window closure. This is a bounded addition to the existing motion, implemented with focused TDD and an independent code review; no new subsystem or plan is needed.
