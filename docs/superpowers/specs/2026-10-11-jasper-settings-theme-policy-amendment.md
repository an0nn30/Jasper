Approved controller rulings, 2026-10-11. This amends Theme Engine Plan 3 Task 9; original reference and behavior obligations remain binding.

## Persisted theme policy

Add opt-in `ui.theme.follow_system=false`, retaining `ui.theme.name` and aliases. Add `ui.theme.source=catalog|bundled`, default catalog: catalog means exactly the existing case-insensitive installed-name precedence; bundled resolves only actual authored bundled sources. Unknown bundled names retain their requested value with honest missing-source diagnostic/fallback, never a same-name installed substitute. Existing absent/default source configuration and arbitrary names retain their meaning.

Dark/Light tiles exit system policy. They retain the resolving manual name and origin when its authored polarity matches; otherwise they stage the corresponding actual Jasper Dark/Jasper Light bundled name and bundled origin. Match System retains both remembered manual fields, chooses the real bundled source directly from ongoing OS preference, and never guesses custom pairs or inverts colors. A named chooser selection stages its explicit name/origin and exits system mode. Disambiguate actual bundled choices when a catalog name shadows them; imported themes use catalog. Origin is part of the coupled editor, never an implementation-facing Source form row. Only meaningful duplicate-choice labels and missing-source diagnostics expose it.

External custom-name edits set source=catalog (or remove it) and follow_system=false. Explicit bundled plus unknown name remains a missing bundled request. Coupled reset restores schema defaults. Independent workspace names retain catalog semantics; workspace match follows effective chrome. OS changes never write configuration, mark Settings dirty or rebase its draft. An unavailable observer preserves intent and uses the remembered manual source with diagnostic; recover when valid observations return.

## Task9b app-only receiving and inline editing contracts

Controller-approved bounded additions are in jasper-ui; SDK descriptors, host projection and testkit ABI are unchanged. Existing consumers remain usable without initialization ceremony.

- `EncodedArtwork(Format, byte[])` is a defensive, content-equal SVG/PNG value with redacted diagnostics. `prepare()` validates and creates its private immutable decoded snapshot once, including cached rejection. Runtime management publishes only after worker preparation, and retains the exact value for all four consumers. A malformed decorative icon never fails startup or a successful manager outcome. Direct registry users may omit preparation: registration performs a bounded one-time fallback. No global cache, jar callback, resource lookup or decode is permitted in repeated paint.
- `IconRegistry.register(name, EncodedArtwork)` is atomic; existing path registration/raw multicolor host artwork remain intact. Encoded RGBA/intrinsic aspect ignore foreground tint. SVG preflight disables DTD/entities/external/data/CSS imports/scripts and retains local fragments; actual resource denial is also enforced by JSVG. Encoded bytes are limited to256KiB, viewport dimensions4096 and raster pixels4,194,304. Per-extent1×/2×/3× receiving snapshots are prepared outside painting in a bounded cache. Direct SVG coverage avoids aliasing from extreme master-image minification; PNG uses progressive reduction. Disabled image/tile opacity is applied once by the receiving label, not by a second LAF filter.
- `ReceivingArtwork` owns unique aliases on the existing context registry. Reconcile retains old/new aliases during publication, prunes only after success, and preserves attempted generations if publication fails. Old Icon snapshots remain valid. Full lists retain aliases while filtering or virtualization hides rows. Views detach before receiver close; receiver close never closes the borrowed registry. Notification editor aliases are retained until its owning page closes, avoiding retirement beneath an unpublished descriptor. Schema and Settings cleanup attempt every resource and suppress later failures; repeated close is inert.
- `KitView.setArtworkPresentation(id, DEFAULT|IDENTITY_ROW|IDENTITY_HEADER)` chooses engine roles, not caller tile numbers. Stable icon IDs retain presentation across updates/theme/scale; invalid IDs/types reject without realizing a virtual row or changing selection. Removal/type replacement/close clear metadata. Row30/glyph17, header52/glyph26 and47row pitch are source measurements. Identity NAVIGATION reuses fixed-action/flexible-identity layout, themed status-dot/caption pairing and compact sections. The shared native split UI paints its allocated separator in the lightweight owner: this fixes headless print omission of the correctly allocated AWT divider, not a proven native missing-line defect. Hit/drag allocation is unchanged; native proof remains open.
- `attachTreeDetail(treeId, itemId, ViewSpec, events, detached)` attaches one standard-descriptor child view beneath a visible leaf. Custom nodes are rejected. The tree owns it independently of recycled rows; one generation cannot close its successor. Collapse/filter/removal/page-away/close retire controls/listeners and notify once after detachment. Stable updates preserve child controls. Header/detail height, hit tests, following rows and scroll/reveal use the same variable geometry. Parent hidden/disabled/busy state gates the child.
- `setTreeRowPresentation` and `setButtonKeycaps` use immutable `KeycapSequence` and `TreeRowPresentation`. The engine owns passive cap outlines, spacing and width-dependent wrapping. The app formats actual KeyStroke values; it never reparses drawn strings. Spoken chord/read-only context stay accessible. Removing presentation restores ordinary controls. Core section glyphs come from authored catalog metadata, never plugin display-name guesses; modified section dots reflect real draft differences.
- `setFieldTrailing(fieldId, Optional<Button>)` owns a normal ButtonControl inside mounted TEXT/SEARCH fields, preserves input/document/caret/selection/undo and validates full source IDs, other retained adjuncts, eligibility and icon before replacement. Failed replacement retains the prior child. Same field ID/kind persists; removal/type replacement/close clears listeners, ownership and properties. Parent state, traversal, event/focus routing and input focus return are owned. Clear stays a separate action. `setFieldReadOnly` affects only editability and accessible editable state; Stop/Clear remain enabled subject to ordinary parent state. Search capture suppresses native text mutations while keeping focus/copy/selection.
- `setButtonValuePresentation(id, DEFAULT|RECORDER|RECORDER_ARMED)` retains the existing actionable button. Recorder uses input/focus/error roles, left-aligned placeholder or caps, and one armed indicator. Empty keycaps restores descriptor text independently from recorder role. Identity/action/accessibility/state survive updates/theme; reset/removal/close are deterministic. Receiver-aware navigation wraps actions before value/action loss; ordinary absent-role controls keep their treatments.

Ordinary edit Return calls Set only when valid/consented/not busy; Escape cancels the edit. Literal mode captures one nonmodifier, including Return/Escape, then returns to ordinary editing. Search mode still captures all keys. Owned pressed/repeat/typed/released tails drain after editor hiding; open menu paths and foreign windows retain precedence. Remove/Restore remain discoverable real menu actions. Plugins operations remain immediate and are not rolled back by Settings Cancel. Existing consent/inspection/removal late-owner guards, literal selectable Details and restart conversation remain authoritative. Task9b owns the Settings-visible RestartFlow banners; Task9c owns generic chooser/remaining restart behavior.

Declared identity hue is deliberately neutral in9b. Original Remote/Snippets/Sample/header tile colors remain a visible mismatch assigned to immediately following earlyTask10. No inference from image pixels, plugin-ID map, recoloring external art or unversioned manifest addition is allowed. EarlyTask10 must settle strict-parser/version/compatibility/docs for optional declared hue alongside the approved bounded original-icon foundation, then carry final typography/native residuals through Task11.
