# Apache MINA sshd 2.19.0 — server-side facts for File Server's SFTP engine

> Research notes behind `docs/superpowers/plans/2026-10-01-file-server-fs3.md` (File Server FS-3), gathered on
> 2026-10-01. They were checked against the 2.19.0 `-sources.jar`s and by running small experiments on JBR 25 / macOS
> with sshd-core/common/sftp 2.19.0, bcprov-jdk18on 1.85.2 and slf4j-jdk14 2.0.13. The experiment programs mentioned
> below (`exp/E*.java`, `Rec.java`) lived in a temporary scratch folder and are not in the repository; the facts
> stand on their own. "RUN" means observed, "SRC" means read from source only, and "UNVERIFIED" is called out.


Package prefixes: server `org.apache.sshd.server.*` (sshd-core), `org.apache.sshd.common.*` (sshd-common + core), SFTP `org.apache.sshd.sftp.{server,client,common}` (sshd-sftp).
Properties: `org.apache.sshd.core.CoreModuleProperties` and `org.apache.sshd.sftp.SftpModuleProperties`; set with `PROP.set(sshd, value)` (`Property.set(PropertyResolver, T)`; `SshServer` is the resolver).

## 1. SshServer setup

```java

sshd.setHost("127.0.0.1");        // String, comma-separated list allowed; null/empty => bind all interfaces
sshd.setPort(0);                  // int; 0 => ephemeral; after start() getPort() returns the REAL port (RUN: 53405)
sshd.setKeyPairProvider(KeyPairProvider);                    // REQUIRED (checkConfig: "HostKeyProvider not set")
sshd.setPasswordAuthenticator(PasswordAuthenticator);
sshd.setPublickeyAuthenticator(PublickeyAuthenticator);      // see DANGER below
sshd.setKeyboardInteractiveAuthenticator(KeyboardInteractiveAuthenticator); // null allowed
sshd.setUserAuthFactories(List<UserAuthFactory>);            // explicit factory list wins over everything
sshd.setSubsystemFactories(List<? extends SubsystemFactory>); // e.g. List.of(sftpSubsystemFactory)
sshd.setShellFactory(ShellFactory) / setCommandFactory(CommandFactory)   // both null by default
sshd.setFileSystemFactory(FileSystemFactory)                 // REQUIRED non-null (checkConfig)
sshd.setForwardingFilter(ForwardingFilter) / setAgentForwardingFilter / setX11ForwardingFilter / setTcpForwardingFilter
```

### Disabling keyboard-interactive (RUN, E3)
`ServerAuthenticationManager.resolveUserAuthFactories`: if `userAuthFactories` is empty it builds them from the authenticators: password authenticator => **password + keyboard-interactive**,
plus publickey if a pubkey authenticator is set. To disable KI, set the list explicitly:
```java
sshd.setUserAuthFactories(List.of(
    org.apache.sshd.server.auth.password.UserAuthPasswordFactory.INSTANCE,     // type UserAuthFactory
    org.apache.sshd.server.auth.pubkey.UserAuthPublicKeyFactory.INSTANCE));
sshd.setKeyboardInteractiveAuthenticator(null);   // belt and braces
```
RUN: a client restricted to `keyboard-interactive` then fails with `SshException: No more authentication methods available`. (`setUserAuthFactoriesNames("password,publickey")` also exists.)
Also hostbased/GSS authenticators are null by default -> those methods are not offered.

### Shell / exec / subsystem requests (RUN E2/E3b, SRC ChannelSession)
- shellFactory == null: `handleShellParsed` returns `ReplyFailure` (debug log only). commandFactory == null: `log.warn("handleExec({}) No command factory for command: {}")` then `ReplyFailure`. Unknown subsystem name: `WARN "Unsupported subsystem"` -> `ReplyFailure`.
- The channel itself OPENS fine (session channel open succeeds); only the request fails, and the channel is NOT closed by the server.
- Client-visible result: by default the client sends exec/shell with want-reply=false, so NOTHING happens (RUN: `waitFor(CLOSED, 3s)` -> `[TIMEOUT, OPENED]`, `getExitStatus()==null`, channel stays open).
  **To assert refusal in tests** set on the client `CoreModuleProperties.REQUEST_EXEC_REPLY.set(client,true)` and `REQUEST_SHELL_REPLY.set(client,true)`; then `ex.open().verify(..)` still succeeds but the channel
  closes within ms: `waitFor(EnumSet.of(ClientChannelEvent.CLOSED), 3s)` -> `[CLOSED, OPENED]`, `isOpen()==false`, `getExitStatus()==null` (client logs WARN `handleFailure(ChannelExec...) ... command=echo hi`).
- Agent forwarding (`auth-agent-req@openssh.com`): `factory(null) || filter==null || !filter.canForwardAgent` => ReplyFailure. X11 (`x11-req`): `!filter.canForwardX11` => ReplyFailure. With RejectAll both refused. No special switch needed; do not call `setAgentFactory`.
- Port forwarding (RUN):
  * `session.createLocalPortForwardingTracker(local, remote)` succeeds locally (client listens) but each connection through it makes the server refuse `direct-tcpip`; the tracker socket reads EOF.
  * raw `session.createDirectTcpipChannel(local, remote).open().verify(..)` throws `org.apache.sshd.common.SshException: DefaultOpenFuture[...]: Failed (SshChannelOpenException) to execute: Generic error while opening channel: 2`;
    walk causes to `org.apache.sshd.common.channel.exception.SshChannelOpenException#getReasonCode()` == **1** (SSH_OPEN_ADMINISTRATIVELY_PROHIBITED). (The "2" in the message is the channel id, not the reason.)
  * `session.createRemotePortForwardingTracker(...)` throws `org.apache.sshd.common.SshException: Tcpip forwarding request denied by server`.
  * server logs WARN `Failed (SshChannelOpenException) to open channel for session=...` on each refused direct-tcpip.

### start()/stop() behaviour (RUN E2/E10)
- `start()` on a busy port throws **`java.net.BindException: Address already in use`** directly (an `IOException`; no wrapping, no cause chain); sshd also logs SEVERE `bind(/127.0.0.1:53405) - failed (BindException) to bind: Address already in use` (logger `org.apache.sshd.common.io.nio2.Nio2Acceptor`, RUN).
- After a failed `start()`: `isStarted()==false` but `isOpen()==true` and **`stop(..)` is a no-op** (`if (!started.getAndSet(false)) return;`) -> acceptor/IO factory resources stay allocated. Call `sshd.close(true).await(Duration.ofSeconds(5))` (RUN: then `isOpen()==false`).
- An `SshServer` instance is single-use: after `stop()`/`close()` `start()` throws `IllegalStateException("Can not start the server again")`. Build a new `SshServer` per start.
- `stop(false)` blocks "until all resources are disposed" (maxWait = Long.MAX); with a live SFTP session it took 3 ms (sessions are disconnected); `stop(true)` 0 ms, bounded by STOP_WAIT_TIME. Client session was closed in both cases. No non-daemon/sshd threads remained after stop (RUN: thread list empty).
- `isStarted()` true only between a successful start and stop. `getBoundAddresses()` empty after stop.
- Stopping with an open file handle logs `WARNING closeAllHandles(...) failed (ClosedByInterruptException) to close handle=...` (see section 6, closeFile).

## 2. Host key (RUN E1, E9)

`org.apache.sshd.server.keyprovider.SimpleGeneratorHostKeyProvider` (sshd-common): `new SimpleGeneratorHostKeyProvider(Path)`; `setAlgorithm(String)`, `setKeySize(int)`, `setOverwriteAllowed(boolean)` (default true), `setStrictFilePermissions(boolean)` (default true), `getPath()`.
`List<KeyPair> loadKeys(SessionContext)` (pass `null` for offline use) generates-or-loads once and caches (RUN: second call returns the same key).

- **Ed25519 needs `setAlgorithm("Ed25519")`** (= `SecurityUtils.ED25519`). `"EdDSA"` (= `SecurityUtils.EDDSA`) FAILS with BC-only: `Failed (IllegalStateException) to generate EdDSA key-pair: generator not correctly initialized` (WARN, swallowed) and `loadKeys` returns an EMPTY list -> server would start and every handshake fail. Default algorithm is `"EC"` (largest curve => nistp521). `"RSA"` + `setKeySize(3072)` also works. Ed25519 takes no key size.
- Works with only BouncyCastle on the classpath (no net.i2p): generated `org.bouncycastle.jcajce.provider.asymmetric.edec.BC15EdDSAPublicKey`, `getAlgorithm()=="Ed25519"`, `KeyUtils.getKeyType(kp)=="ssh-ed25519"`. `SecurityUtils.isEDDSACurveSupported()==true`, `isBouncyCastleRegistered()==true`.
  No explicit setup needed: first use of `SecurityUtils` registers the BC registrar automatically when bcprov is on the classpath (INFO `getOrCreateProvider(BC) created instance of org.bouncycastle.jce.provider.BouncyCastleProvider`; `Security.getProviders()` then contains `BC version 1.8502`).
  **Plugin-classloader hazard (SRC + Remote plugin comment):** the default registrar uses the *named* provider "BC" from the JVM-global `java.security.Security` (`AbstractSecurityProviderRegistrar.getOrCreateProvider`: `Security.getProvider(getProviderName())` first), which can belong to another plugin's BC classes. Remote does this in a static initializer before first sshd use
  (`plugins/remote/.../client/Connections.java` lines 48-55):
  ```java
  SecurityUtils.registerSecurityProvider(new org.apache.sshd.common.util.security.bouncycastle.BouncyCastleSecurityProviderRegistrar() {
      private final java.security.Provider local = new org.bouncycastle.jce.provider.BouncyCastleProvider();
      @Override public boolean isNamedProviderUsed() { return false; }
      @Override public java.security.Provider getSecurityProvider() { return local; }
  });
  ```
  A File Server plugin bundling its own sshd+BC needs the same snippet (each plugin has its own `SecurityUtils` statics). Not reproducible outside the plugin loader: UNVERIFIED at runtime.
- File format: unencrypted OpenSSH private key (`-----BEGIN OPENSSH PRIVATE KEY-----`, 7 lines/399 bytes for Ed25519) written by `OpenSSHKeyPairResourceWriter` with comment "host key". Reload gives the same fingerprint.
- Permissions: after creating an empty file it applies `File.setReadable(false,false)&&setReadable(true,true)`, same for write, `setExecutable(false)` (POSIX) / ACL rewrite (Windows) => RUN: **`rw-------`**. Not re-applied when loading an existing file (RUN: a 0644 file stays 0644). Parent directory is NOT created.
- Silent failure modes (all just WARN logs, no exception):
  * parent dir missing / unwritable: `Failed (NoSuchFileException) to write Ed25519 key` -> returns an **in-memory throwaway key** (new fingerprint every start). Create the directory first and assert the file exists after `loadKeys`.
  * file present but unparsable (RUN: "this is not a key"): **silently regenerated and overwritten** (new fingerprint). With `setOverwriteAllowed(false)` it uses a throwaway key and leaves the file untouched (WARN "Overwriting host key (...) is disabled: using throwaway ssh-ed25519 key").
  * file holds a different algorithm than requested (EC file, Ed25519 requested): file deleted and regenerated.
- Fingerprint, OpenSSH `SHA256:` form (RUN, matches `ssh-keygen -lf`):
  ```java
  KeyPair kp = provider.loadKeys((SessionContext) null).get(0);
  String fp = org.apache.sshd.common.config.keys.KeyUtils.getFingerPrint(
          org.apache.sshd.common.digest.BuiltinDigests.sha256, kp.getPublic());   // "SHA256:IaVZXa2t...qc" (base64, no padding)
  String line = org.apache.sshd.common.config.keys.PublicKeyEntry.toString(kp.getPublic()); // "ssh-ed25519 AAAAC3Nz..."
  ```
  `KeyUtils.getFingerPrint(PublicKey)` (default digest) also returns the SHA256 form. Signatures: `static String getFingerPrint(Factory<? extends Digest> f, PublicKey key)`, `static String getFingerPrint(PublicKey)`; on exception they return the exception's toString, never throw.

## 3. Authenticators

```java
// org.apache.sshd.server.auth.password.PasswordAuthenticator   (@FunctionalInterface)
boolean authenticate(String username, String password, ServerSession session)
        throws PasswordChangeRequiredException, AsyncAuthException;
default boolean handleClientPasswordChangeRequest(ServerSession, String user, String oldPw, String newPw)  // throws UnsupportedOperationException by default
// org.apache.sshd.server.auth.pubkey.PublickeyAuthenticator    (@FunctionalInterface)
boolean authenticate(String username, PublicKey key, ServerSession session) throws AsyncAuthException;
static PublickeyAuthenticator fromAuthorizedEntries(Object id, ServerSession session,
        Collection<? extends AuthorizedKeyEntry> entries, PublicKeyEntryResolver fallbackResolver)
        throws IOException, GeneralSecurityException;     // empty/null entries => RejectAllPublickeyAuthenticator.INSTANCE
```
- Remote address: `org.apache.sshd.server.session.ServerSession#getClientAddress()` -> `SocketAddress` (RUN: `java.net.InetSocketAddress`, e.g. `/127.0.0.1:54704`); also `Session#getRemoteAddress()` (the raw socket peer; equals client address unless a ServerProxyAcceptor is used). `session.getUsername()` is null before auth completes (RUN: logs show `null@/127.0.0.1:..`).
- false vs throw (RUN E7, SRC UserAuthPassword/UserAuthPublicKey/ServerUserAuthService): returning `false` => USERAUTH_FAILURE silently. Throwing any `Exception` (RUN: IllegalStateException) is caught in `ServerUserAuthService.handleUserAuthRequestMessage`, logged **WARNING with stack trace** (logger `org.apache.sshd.server.session.ServerUserAuthService`), and treated as failure -> same client-visible result as `false`. Throwing an `Error` is rewrapped as `RuntimeSshException`. `PasswordChangeRequiredException` => sends SSH_MSG_USERAUTH_PASSWD_CHANGEREQ (auth stays "in progress"). `AsyncAuthException` => async completion. Always return false.
- **Public-key authenticator is called TWICE for one successful login** (RUN: 2 calls, both `authenticate(alice, key)`), once for the unsigned "query" (`hasSig==false`; on true sshd answers `SSH_MSG_USERAUTH_PK_OK`) and once for the signed request (SRC `UserAuthPublicKey.doAuth`):
  ```java
  authed = authenticator.authenticate(username, key, session);   // BEFORE signature verification
  if (!authed) return Boolean.FALSE;
  if (!hasSig) { sendPublicKeyResponse(...); return null; }
  ... verifier.initVerifier(session, verifyKey); if (!verifySignature(...)) throw new SignatureException("Key verification failed");
  ```
  An unauthorized key => exactly 1 call (query, false) (RUN). Right key + wrong username => 1 call. Authenticator returning true does NOT mean authenticated: a bad signature happens after it and surfaces only as a WARN stack trace + failure.
  => For throttling, count attempts in the authenticator (password: 1 call/attempt; pubkey: 1 call for a rejected key, 2 for an accepted one) and clear the counter on success via `SessionListener.sessionEvent(Session, SessionListener.Event.Authenticated)`.
- The built-in `AuthorizedKeyEntriesPublickeyAuthenticator` (what `fromAuthorizedEntries` returns) ignores the username and **does not enforce** any option (`command=`, `from=`, `restrict`, `no-pty`, `principals` only for certs); it only stores the matched entry in session attribute `AuthorizedKeyEntriesPublickeyAuthenticator.AUTHORIZED_KEY`. Enforce restrictions yourself.
- Session-level hooks for accounting: `SessionListener` (`org.apache.sshd.common.session`): `default void sessionCreated(Session)`, `sessionEstablished(Session)`, `sessionEvent(Session, Event)` (`Event.KeyEstablished|Authenticated|KexCompleted`), `sessionException(Session, Throwable)`, `sessionDisconnect(Session, int reason, String msg, String language, boolean initiator)`, `sessionClosed(Session)`; register with `sshd.addSessionListener(l)`. `sessionCreated` gives the peer address pre-auth (use for per-IP connection caps).
- Auth disconnect INFO logs come from `org.apache.sshd.common.session.helpers.SessionHelper` ("Disconnecting(...): ...").

## 4. authorized_keys parsing (RUN E8)

`org.apache.sshd.common.config.keys.AuthorizedKeyEntry extends PublicKeyEntry`:

## 5. SFTP subsystem factory and listener

```java
SftpSubsystemFactory f = new SftpSubsystemFactory.Builder()     // org.apache.sshd.sftp.server
        .withFileSystemAccessor(SftpFileSystemAccessor)         // default SftpFileSystemAccessor.DEFAULT
        .withUnsupportedAttributePolicy(UnsupportedAttributePolicy) // Ignore | Warn (default) | ThrowException
        .withExecutorServiceProvider(Supplier<? extends CloseableExecutorService>)
        .withSftpErrorStatusDataHandler(SftpErrorStatusDataHandler)
        .withErrorChannelDataReceiver(ChannelDataReceiver)
        .build();
boolean added = builder.addSftpEventListener(l);   // Builder and factory both extend AbstractSftpEventListenerManager; returns boolean (not fluent); also removeSftpEventListener
```
- `SftpSubsystemFactory.NAME == "sftp"`. Listeners registered on the factory are copied to each new `SftpSubsystem` (one per channel). Supported protocol versions 3..6 (RUN: client negotiates v6). Without an executor provider each subsystem gets its own single-thread executor; **if you supply a provider, `destroy()` calls `shutdownNow()` on whatever `provider.get()` returned, so return a fresh executor per call, never a shared pool.**
- A server `SftpEventListener` (`org.apache.sshd.sftp.server.SftpEventListener extends SshdEventListener`), all `default`, all `throws IOException`, `ServerSession` = `org.apache.sshd.server.session.ServerSession`:

- **Vetoing by throwing (RUN E5, all 10 hook types tested: opening, writing, reading, removing, moving, creating, linking, modifyingAttributes, readingEntries, receivedExtension):** the exception is caught in the request handler (`catch (IOException | RuntimeException e) -> sendStatus(...)`), the operation is NOT performed and the client gets an `SSH_FXP_STATUS` whose code comes from `SftpHelper.resolveSubstatus(Throwable)` and a GENERIC message (never the exception text/path):
  * plain `IOException` or any RuntimeException -> `SSH_FX_FAILURE` ("General failure")
  * `java.nio.file.AccessDeniedException` -> `SSH_FX_PERMISSION_DENIED` ("Permission denied"); `NoSuchFileException` -> NO_SUCH_FILE; `FileAlreadyExistsException`; `DirectoryNotEmptyException`; `NotDirectoryException`; `InvalidPathException` -> INVALID_FILENAME; `UnsupportedOperationException` -> OP_UNSUPPORTED
  * `org.apache.sshd.sftp.common.SftpException(int status, String msg)` -> that exact status (RUN `SSH_FX_WRITE_PROTECT` -> "File/Directory is write-protected"; `SSH_FX_PERMISSION_DENIED` -> "Permission denied")
  Client side: `org.apache.sshd.sftp.common.SftpException#getStatus()` (high-level `readEntries/readDir(String)` wrap it in `UncheckedIOException`). The SFTP session stays usable afterwards (RUN: stat succeeded after vetoes). The *-ed callbacks (`removed`, `moved`, ...) receive the thrown vetoing exception only when thrown by the accessor, not when thrown by the matching *-ing listener (the *-ing throw skips the *-ed call).
- Hooks that do NOT exist for some mutating ops: `copy-file@` (extension `copy-file`) calls `accessor.copyFile` with no listener hook except `receivedExtension` and `received`; so a read-only mode must veto `receivedExtension("copy-file")` (or override `accessor.copyFile`). `copy-data` writes via a write handle (`writing` is NOT called for it; it calls `FileHandle.write` directly) -> gate on `opening` WRITE options. SETSTAT size/truncate uses `accessor.openFile(null handle, WRITE)` -> gate via `modifyingAttributes`. Hash extensions (md5-hash, check-file-name) open read-only via `accessor.openFile(..., emptySet)` without listener events.
- To implement "read-only", veto: `opening` where `handle instanceof FileHandle fh && (fh.getOpenOptions() contains WRITE/CREATE/CREATE_NEW/TRUNCATE_EXISTING/APPEND)`, `creating`, `removing`, `moving`, `linking`, `modifyingAttributes`, `receivedExtension` for copy-file / copy-data / hardlink / posix-rename / lsetstat (the last four also hit linking/moving/modifyingAttributes).
- `received`/`receivedExtension` are the universal gates (exception => status for that request id).
- Errors surface in `SftpErrorStatusDataHandler` (`resolveSubStatus`, `resolveErrorMessage`, `resolveErrorLanguage`; defaults: generic text) -> no host path leakage in error messages.

### What the subsystem does DIRECTLY on Paths, bypassing the accessor (SRC AbstractSftpSubsystemHelper / SftpSubsystem + RUN traces)
Legend: A = through accessor; D = direct `Files.*` / `IoUtils.*` on the Path returned by `resolveLocalFilePath` (so the Path itself must be safe); `normalize` = `abs.normalize()` (lexical only). **`toRealPath()` is never used anywhere in the SFTP server.**
- OPEN: A resolveLocalFilePath -> `new FileHandle` -> listener.opening -> A openFile (default impl itself does `Files.exists`) -> listener.open. No directory/exist pre-checks.
- OPENDIR: A resolve + **normalize**, then D `IoUtils.checkFileExistsAnySymlinks`, D `Files.isDirectory`, D `Files.isReadable`, then A openDirectory (at DirectoryHandle construction).
- READDIR: D `checkFileExistsAnySymlinks`/`Files.isDirectory`/`Files.isReadable` on the dir for EVERY READDIR request; entries from the A DirectoryStream; each entry stat'ed with NOFOLLOW via A readFileAttributes + D `IoUtils.checkFileExists` + D `FileInfoExtractor` (`Files.isRegularFile/isDirectory/isSymbolicLink/size/getLastModifiedTime/permissions` when a view lacks them) + A resolveReportedFileAttributes + A putRemoteFileName. `.` is synthesized from `dir`, `..` from `dir.getParent()` **even on the native FS** (RUN: `..` listed at the jail root with the real parent's attributes; with the rooted FS root has no parent so no `..`).
- STAT / LSTAT / FSTAT: A resolve, A resolveFileAccessLinkOptions, D `checkSymlinkState` (`IoUtils.checkFileExists`; if `!AUTO_FOLLOW_LINKS` also `Files.readAttributes(NOFOLLOW)` of every parent prefix), A readFileAttributes, D FileInfoExtractor fill-ins, A resolveReportedFileAttributes.

- RMDIR: A resolve; D `Files.isDirectory(p, NOFOLLOW)` (so a symlink-to-dir is "not a directory"); listener.removing; A removeFile.
- REMOVE: A resolve; D `checkSymlinkState`, D `Files.isDirectory(NOFOLLOW)`; listener.removing; A removeFile. Removing a symlink removes only the link (RUN) but removing `/link-dir/file` deletes the target outside (RUN).
- RENAME / posix-rename@openssh.com: A resolve x2, listener.moving, A renameFile. No D checks.
- READLINK: A resolve, A resolveLinkTarget, A putRemoteFileName (target text unmodified: RUN rooted FS shows `/../outside` for an absolute outside link).
- SYMLINK / LINK / hardlink@openssh.com: `link` = A resolve(linkPath); `existing` = **`fileSystem.getPath(existingPath)` (not via accessor)**; listener.linking; A createLink.
- copy-file: A resolve x2; A copyFile (no listener). md5-hash: A resolve, A resolveFileAccessLinkOptions(follow=true), D `Files.isDirectory`, D `Files.size`, A openFile(null, emptySet)/closeFile. check-file-name: A resolve then a D loop `Files.isSymbolicLink`/`Files.readSymbolicLink` (up to 127 hops, manual follow), D `Files.isDirectory`, D `Files.size`, A openFile/closeFile. *-handle variants use the handle's path (`Files.size` D).

Dispatch table: text-seek, version-select, copy-file, copy-data, md5-hash, md5-hash-handle, check-file-handle, check-file-name, fsync@openssh.com, space-available, hardlink@openssh.com, lsetstat@openssh.com, posix-rename@openssh.com, limits@openssh.com.

* LSTAT reports the link as `symlink=true`; STAT follows it (so a client can see through).
**=> A symlink jail must be added in an accessor** (or by refusing/removing symlinks): e.g. `resolveLocalFilePath` returning a native `Path` after `deepestExistingAncestor.toRealPath().startsWith(realRoot)` (PoC `exp/E6.java` class `Jail`, RUN): on the native FS (`sshd.setFileSystemFactory(NativeFileSystemFactory.INSTANCE)`; the accessor ignores `rootDir`) with `resolveLocalFilePath` = normalize-as-absolute + real-path check, `putRemoteFileName` stripping the real root prefix, `createLink`/`resolveLinkTarget` throwing AccessDeniedException => `canonicalPath(".")=="/"`, `/sub/../..`->`/`, `/../../../etc/hosts` clamped inside root, `/link-out-file` read -> PERMISSION_DENIED, `/link-out-dir/new.txt` write -> PERMISSION_DENIED, hardlink `existing=/etc/hosts` -> PERMISSION_DENIED. * Rooted-FS mapping: remote string -> `rootDir.resolve(translated)` -> `RootedPath` (absolute within the rooted FS; `Path.toString()` is the client-visible path like `/sub/a.txt`; `..`-containing paths stay un-normalized, e.g. `/../../etc`) -> `provider.unroot()` -> host path `<root>/...` inside every FS call. Pass `root.toRealPath()` to `VirtualFileSystemFactory`. With a real path it works (36-byte reply, host volume stats).

## 10. 2.19.0 gotchas / differences from older docs
1. Properties live in `CoreModuleProperties` / `SftpModuleProperties` (`Property<T>`), not `FactoryManager.*` string constants / `PropertyResolverUtils` keys (use `PROP.set(sshd, value)`; durations are `Duration`).
2. `setUpDefaultServer()` is NOT secure-by-default for auth/FS: default pubkey authenticator reads the OS user's `~/.ssh/authorized_keys`; KI silently mirrors the password authenticator; default FS is native. Set `setPublickeyAuthenticator`, `setUserAuthFactories`, `setFileSystemFactory` explicitly.
3. `setAlgorithm("EdDSA")` fails silently with BC-only; use `"Ed25519"`. Host key provider swallows generation/IO errors (empty list or throwaway key) -- verify `loadKeys(null)` is non-empty and the file exists afterwards; corrupt file is overwritten.
4. Failed `start()` leaves the server open; `stop()` is then a no-op -> `close(true)`. Server instances are not restartable.
5. `SftpFileSystemAccessor`: `openFile` returns `SeekableByteChannel` (not `FileChannel`); `resolveFileAccessLinkOptions`, `resolveReportedFileAttributes`, `putRemoteFileName`, `noFollow` and the static `secure*` helpers are the "newer" members (SSHD-1137/1226/1132); `resolveLocalFilePath` gets `SftpSubsystemProxy` + `rootDir`. `SftpEventListener` has `received`/`receivedExtension`/`exiting`/`openFailed` in addition to the classic ones, and `moving/removing/creating/linking` pass `Path`s of the server FS (RootedPath for the rooted FS).
6. `AUTO_FOLLOW_LINKS` defaults true, so the "never follow symlinks in parent dirs" validation branches (`validateParentExistWithNoSymlinksIfNeverFollowSymlinks`, `checkFileExistsAnySymlinks(..., true)`) are skipped unless you set `SftpModuleProperties.AUTO_FOLLOW_LINKS.set(sshd,false)`. UNVERIFIED whether setting it false is a complete symlink defence (it only adds non-atomic NOFOLLOW prefix checks, per the source comment "leaves a nasty race condition"); the NOFOLLOW path in `openFile` additionally needs a `SecureDirectoryStream` (RUN: `RootedSecureDirectoryStream` is returned on macOS; unknown elsewhere).
7. `copy-file`, `space-available`, `md5-hash`, `check-file-name`, `hardlink@openssh.com` are always live regardless of advertised extensions.
8. Exec/shell refusal is silent unless the client asks for a reply (see section 1).
9. sshd has no failed-auth delay, no per-IP limit, no pre-auth connection cap.
10. JDK 25 + BC 1.85.2 + sshd 2.19.0 worked unmodified (no `--add-opens`, no net.i2p). `Security.getProviders()` gains a JVM-global `BC` entry when the default registrar is used (see section 2 for the plugin-classloader workaround).
