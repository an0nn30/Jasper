Overview

Jasper is a pluggable DevOps workstation for macOS, Linux and Windows. The application itself provides the workspace (windows, tabs, panes and tool windows), the terminal, the command palette, notifications, Settings, themes and looks. Most of what you use beyond that, from SSH sessions to the credential vault, ships as plugins written against this SDK, and a plugin you write uses the same API as the plugins Jasper ships with. Bundled plugins differ in a few rules: they need no capability review, only they can be off by default, they load in safe mode unless they provide a look, and they take precedence for the editor role and for a subcommand name two loading plugins declare.

What a plugin can do

  • Commands and chromeActions that appear in the command palette and Settings › Keymap with default shortcuts, placed in menus, the toolbar, the status bar and the tool window stripe.
  • Tool windows, tabs and dialogsDocked tool windows, content tabs that split, move between windows and come back when Jasper restores its windows, items in the Split lists, dialogs, in-window overlays and popovers, all built from declarative views that Jasper draws.
  • TerminalsFind windows, tabs and panes, read what a pane runs, type into it, open local tabs, splits and programs, add environment variables to new shells, and follow 17 terminal events.
  • SessionsProvide a pane's session over its own connection, as Remote does for SSH: Jasper owns the pane, its banner and Reconnect.
  • Command paletteScopes of searchable rows with up to three verbs, an optional form step, recents, and a chip the user reaches by prefix or shortcut.
  • Notifications and activityNotification groups the user tunes in Settings, long-running activities and connection states shown on Desk Buddy.
  • SettingsTyped, validated settings in the plugin's own TOML file, read live, with a generated page in Settings › Tools or a page of the plugin's own.
  • Files and the editorPlaces in Jasper's file chooser, such as saved hosts, and the role of the editor Jasper opens files with.
  • Services for other pluginsInterfaces in an exported package that other plugins look up, as the Vault, Editor, Remote and Snippets plugins do.
  • The command line{@code jasper } subcommands that run in the running Jasper and report an exit code.
  • Looks and themesA look (the presentation of the chrome and controls) and themes, declared as data in the manifest; any plugin can read which look Jasper runs with and compose for it.

How a plugin runs

A plugin is a folder of jars, one of which holds a {@code plugin.toml} manifest at its root. Jasper finds plugins once, when it starts, in three places: the plugins bundled in the application, the {@code plugins} folder in Jasper home, and the folder given with {@code --plugin-dir}. It checks each manifest, the SDK range, the plugin's dependencies and, for a plugin the user installed, the user's consent to its capabilities. It then loads each plugin in its own class loader, dependencies first, and calls its {@link Plugin#start(PluginContext)} on the UI thread with a {@link PluginContext} of its own. Jasper home is the folder that holds {@code config.toml}: {@code ~/.config/jasper} on macOS, {@code $XDG_CONFIG_HOME/jasper} (or {@code ~/.config/jasper}) on Linux and {@code %APPDATA%\jasper} on Windows, unless {@code JASPER_HOME} or the {@code jasper.home} Java property moves it; see configuration.

A plugin's class loader sees the SDK, the Java runtime, the plugin's own jars and the packages that plugins it requires export; Jasper's own classes and libraries are not visible. Everything a plugin registers through its context is attributed to it and removed when it stops. Nothing loads or unloads while Jasper runs: installing, updating, enabling, disabling and removing a plugin take effect at the next launch.

The SDK depends only on the JDK. A few signatures use AWT and Swing types: colours ({@code java.awt.Color}), a component's workspace opacity ({@code java.awt.Component}), custom content ({@code javax.swing.JComponent}) and content-tab shortcuts ({@code javax.swing.KeyStroke}). Plugins run on Java 25.

The bundled plugins

Each bundled plugin is an ordinary plugin on this SDK: it declares capabilities, requires other plugins and exports packages exactly as yours would, and each can be turned off in Settings › Plugins. Every one declares {@code sdk = ">=0.23.0, <0.24"}.

The Sample plugin is the SDK's end-to-end example and shows nothing until one of its {@code demo_*} settings is on. The exported packages and what they offer are described in Services and, for users of those plugins, in plugin APIs. The user's side of plugins (installing, reviewing, safe mode) is in plugins.

Packages

The SDK ({@code jasper-sdk}) is 12 packages under {@code dev.jasper.sdk}. The test kit ({@code jasper-sdk-testkit}) adds {@code dev.jasper.sdk.testing}, and the bundled plugins' exported packages complete the API reference below.

Using this reference

The guide pages explain how the parts work together; the API reference after them documents every public type and member, grouped by package. Press / to search types and members. Worked examples taken from the Sample plugin are in plugin authoring, view compositions in plugin UI and icon rules in plugin icons.
