Testing

The test kit, {@code jasper-sdk-testkit-{@sdk.version}.jar}, runs a plugin headless in a unit test. Its {@link FakePluginHost} is a single-threaded stand-in for Jasper's plugin runtime with the same rules: queued event delivery, topic ownership, services committed only after a successful start, rollback and a closed context after a failed one, capability checks and namespaced ids. The test scripts the workstation (windows, panes, settings, commands) and reads back what the plugin contributed as plain lines. The kit depends only on the SDK; put both jars on the test classpath, as the quick start's build does. See also the test kit's README.

A test

The plugin under test types a configured command into a pane from the pane's context menu, and prints it from a {@code jasper} subcommand:

package dev.example.deploy;

import dev.jasper.sdk.plugin.Plugin;
import dev.jasper.sdk.plugin.PluginContext;
import dev.jasper.sdk.settings.EditorHint;
import dev.jasper.sdk.settings.Setting;
import dev.jasper.sdk.settings.SettingKind;
import dev.jasper.sdk.settings.SettingSpec;
import dev.jasper.sdk.ui.ActionSpec;
import java.util.concurrent.CompletableFuture;

public final class DeployPlugin implements Plugin {
    static final String TYPE = "dev.example.deploy.type";

    @Override public void start(PluginContext context) {
        Setting<String> command = context.settings().declare(SettingSpec.of("command",
                SettingKind.text(text -> !text.isBlank(), "Enter a command."), "make check")
            .label("Check command").editor(EditorHint.technical()));
        context.actions().register(ActionSpec.of(TYPE, "Type Deploy Check"),
            invoked -> invoked.pane().ifPresent(pane -> pane.sendText(command.get())));
        context.menus().terminalContext().add(TYPE);
        context.commandLine().handle("deploy-check", call -> {
            call.out(command.get() + "\n");
            return CompletableFuture.completedFuture(0);
        });
    }
}
package dev.example.deploy;

import static org.assertj.core.api.Assertions.assertThat;

import dev.jasper.sdk.Capabilities;
import dev.jasper.sdk.PluginInfo;
import dev.jasper.sdk.terminal.PaneInfo;
import dev.jasper.sdk.terminal.SessionKind;
import dev.jasper.sdk.terminal.SessionState;
import dev.jasper.sdk.testing.FakePluginHost;
import java.nio.file.Path;
import java.util.List;
import java.util.Optional;
import java.util.OptionalInt;
import java.util.Set;
import java.util.UUID;
import org.junit.jupiter.api.Test;

class DeployPluginTest {
    private static final String ID = "dev.example.deploy";
    private static final PluginInfo INFO = new PluginInfo(ID, "Deploy", "1.0.0", Set.of(Capabilities.TERMINAL_INJECT));

    /** Declares the manifest's subcommand, as Jasper would, then starts the plugin. */
    private static void start(FakePluginHost host) {
        host.declareSubcommand(ID, "deploy-check", "Print the deploy check command");
        host.start(INFO, Set.of(), Set.of(), new DeployPlugin());
    }

    @Test void typesTheConfiguredCommandIntoThePane() {
        try (var host = new FakePluginHost()) {
            UUID window = host.addTerminalWindow(), tab = host.addTerminalTab(window, "build");
            UUID pane = host.addTerminalPane(tab, new PaneInfo("zsh", Optional.empty(), Optional.empty(), 80, 24, true,
                SessionKind.LOCAL, Optional.empty(), SessionState.RUNNING, OptionalInt.empty(), "zsh"));
            host.setSetting(ID, "command", "make deploy-check");
            start(host);

            assertThat(host.menu("context")).containsExactly("item:" + DeployPlugin.TYPE);
            assertThat(host.invoke(DeployPlugin.TYPE, window, pane)).isTrue();
            assertThat(host.sent(pane)).containsExactly("write:make deploy-check");
            assertThat(host.failures()).isEmpty();
        }
    }

    @Test void reportsABlankCommandAndUsesTheDefault() {
        try (var host = new FakePluginHost()) {
            host.setSetting(ID, "command", " ");
            start(host);

            assertThat(host.settingsReports(ID)).containsExactly("command: Enter a command.");
            var call = host.call("deploy-check", List.of(), Path.of("/work"));
            assertThat(call.exit()).isCompletedWithValue(0);
            assertThat(call.out()).isEqualTo("make check\n");
        }
    }
}

Threads

The thread that calls the host plays the UI thread. Nothing happens behind the test's back: published events wait until {@link FakePluginHost#flush()} delivers them (including those the deliveries publish), and background tasks wait until {@link FakePluginHost#runBackground()} runs them, one after another, on the calling thread. Run the plugin's {@code start}, and the test, on the Swing event dispatch thread instead when the plugin uses its {@link UiKit}: the kit's views ({@link FakeKit}, {@link FakeKitView}) require the real UI thread.

@Test void buildsItsPanel() throws Exception {
    SwingUtilities.invokeAndWait(() -> {
        try (var host = new FakePluginHost()) {
            host.start(INFO, Set.of(), Set.of(), new TargetsPlugin());
            host.addTerminalWindow();
            host.openPanel("dev.example.tool.targets");
            assertThat(host.panelView("dev.example.tool.targets")).isPresent();
            assertThat(host.failures()).isEmpty();
        }
    });
}

Starting and stopping

{@link FakePluginHost#start(PluginInfo,Set,Set,Plugin)} starts a plugin as Jasper would, with its identity and capabilities, the ids of its hard and optional requirements, and the instance. A plugin whose hard requirement is not active is not started; a {@code start} that throws is rolled back. Start providers before their consumers: each consumer receives the services of the providers it names, made by their factories. {@link FakePluginHost#stopAll()} stops every plugin in reverse order, and {@link FakePluginHost#close()} also delivers what is queued and deletes the temporary folder that holds the plugins' data directories ({@link FakePluginHost#FakePluginHost(Path)} uses a folder the test owns instead). {@link FakePluginHost#failures()} lists every contained failure (throwing starts, stops, handlers, factories and background tasks) as a line; assert it is empty.

Where the fake differs from Jasper

  • Background tasks run one at a time when the test asks; in Jasper each runs at once on a virtual thread of its own, so tasks can overlap.
  • The fake checks the calling thread only for the kit's views, which need the event dispatch thread, and for {@link Appearance}'s colours, palettes, workspace opacity and theme subscriptions, which need the thread that made the host or the event dispatch thread ({@link Appearance#variant()}, {@link Appearance#workspaceVariant()}, {@link Appearance#presentation()} and {@link Appearance#terminalTypography()} answer any thread), and {@link Appearance#onTerminalTypographyChanged(Consumer)}, which needs the event dispatch thread. Calls Jasper refuses off the UI thread with {@code IllegalStateException} (registrations, subscribing, publishing services, handling subcommands, terminal queries, the clipboard) succeed in the fake from any thread.
  • Services: the fake does not check that a service's interface is in one of the provider's exported packages, and an absent optional provider's classes are still on the test classpath, so the {@code NoClassDefFoundError} path cannot be tested with it.
  • Settings live in memory; the fake writes no file. A value of the wrong TOML type rejects only that setting, where Jasper rejects the whole file; {@link FakePluginHost#settingsReports(String)} words integer, number, choice and list rejections with the kind's own message, where Jasper uses its own wording (see Settings); {@code set} completes at once; and {@code number} values keep double precision. A look default the plugin cannot use is listed by {@link FakePluginHost#lookDefaultProblems(String)}, where Jasper logs it as a warning.
  • Palette calls receive {@code maxResults} 5 and macOS glyphs, and {@link FakePluginHost#executeInScope(String,String,String,UUID,UUID)} skips the {@code available} check.
  • {@link Platform#openInEditor(Path)} runs on the calling thread; {@link FileSource#connect(String,WindowOwner)} always receives a window; provided panes report 80 × 24; cancellation handlers run at once.
  • An unavailable subcommand's message names the plugin's id rather than its name.
  • {@link FakePluginHost#restoreTab(String,UUID,String,RestoreState)} puts the restored tab in a new tab at the end of the window's strip; Jasper places it where it was saved, in its tab and pane.
  • {@link FakePluginHost#toolbarViews(UUID)} builds toolbar views for any open window, a child window too; Jasper builds them only in the main window.
  • The fake has no active tool window: {@link Panels#toggle(String,WindowHandle)} and {@link PanelHost#show()} from a panel's own toggle action only toggle or show it, also under {@link FakePresentations#CLASSIC}, where Jasper activates a showing panel that is not the active tool window instead of hiding it.
