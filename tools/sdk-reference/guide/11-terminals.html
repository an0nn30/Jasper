Terminals

{@link PluginContext#terminals()} is the plugin's view of Jasper's windows, tabs and panes. Finding them needs no capability; reading what a pane runs, typing into it, opening terminals and providing sessions do (see Capabilities). Every call is on the UI thread except the three that send input. For the user's side of panes and shell integration, see the terminal.

Windows, tabs and panes

{@link Terminals#activeWindow()} is the window the user used last, even while Jasper is in the background, and {@link Terminals#activePane()} the focused pane of its shown tab, when that pane is a terminal. {@link Terminals#windows()} lists the open windows in opening order, and {@link Terminals#window(UUID)}, {@link Terminals#tab(UUID)} and {@link Terminals#pane(UUID)} find one by the id an event names. An action's {@link ActionContext} gives the window it ran in and the pane it concerns.

{@link WindowHandle}, {@link TabHandle} and {@link PaneHandle} keep only an id; two handles for the same target are equal. A target can close at any moment: {@code isOpen()} tells, queries return the last known value, and commands to it are ignored. A window holds tabs, each holding panes, and each pane one item: a terminal or a plugin's content tab. {@link WindowHandle#tabs()} lists the items tab by tab in strip order, then pane by pane, as {@link TabHandle}s; {@link TabHandle#kind()} says which kind an item is and {@link TabHandle#terminal()} is a terminal's one pane. {@link WindowHandle#isMain()} tells the main window, which keeps an empty workspace when its last tab closes, from a child window, which closes with its last tab. {@link PaneHandle#focus()} shows a pane's tab and focuses the pane, {@link TabHandle#select()} selects an item, and {@link WindowHandle#toFront()} raises a window. A window handle is also a {@link WindowOwner}, for dialogs and choosers over it. Jasper restores its windows at start and whenever the main window opens again: a restored terminal whose tab has not shown yet reports {@link SessionState#NOT_STARTED} until it first shows, and an item Jasper closed with its windows comes back under the same id, so drop a handle on {@link TerminalEvents#TAB_CLOSED}.

Reading a pane

With {@code terminal.observe}, {@link PaneHandle#info()} returns a {@link PaneInfo} snapshot:

FieldMeaning
{@code title}The title the program set, or the running command when it set none.
{@code workingDirectory}The local folder the shell last reported, a hint that may no longer exist. A report counts as local only from a local shell whose report names no host, {@code localhost} or this machine.
{@code remoteDirectory}A {@link RemoteDirectory} (host and path) the shell reported, or the session's provider when the shell reports none; for display only. At most one of the two directories is present.
{@code columns}, {@code rows}The grid size; 0 before the session starts.
{@code shellIntegration}Whether the shell reports its prompts and commands, which the command events need.
{@code kind}, {@code providerPluginId}{@link SessionKind#LOCAL} or {@link SessionKind#PLUGIN}, and the providing plugin.
{@code state}, {@code exitStatus}{@link SessionState#NOT_STARTED} (a restored terminal whose tab has not shown yet), {@link SessionState#CONNECTING}, {@code RUNNING} or {@code EXITED}, and the exit status once it exited with a known one.
{@code shell}The shell or program's label, such as {@code zsh}, or a provided session's title.

{@link PaneHandle#foregroundJob()} asks the operating system for the program in the foreground and completes on a worker thread. {@link TabHandle#title()} is the tab's title as its header shows it. Both need {@code terminal.observe}; {@link PaneHandle#selection()}, the selected text, needs {@code terminal.selection}.

Typing and pasting

With {@code terminal.inject}, {@link PaneHandle#sendText(String)} types text as UTF-8 and adds nothing: end a command with {@code "\r"} to run it, or leave it at the prompt for the user. {@link PaneHandle#sendBytes(byte[])} writes raw bytes, and {@link PaneHandle#paste(String)} pastes the way the user's paste does, bracketed when the program asked for that. The three are safe from any thread, and calls from one thread keep their order. Input to a pane whose session is not running (not started yet, still connecting, or exited) is dropped.

Opening tabs, splits and programs

{@link Terminals#openTab(WindowHandle,OpenRequest)} opens a terminal in a new tab at the end of the window's strip and shows it; {@link Terminals#split(PaneHandle,Direction,OpenRequest)} opens one in a new pane beside the target pane, in its tab, to the {@link Direction#RIGHT} or {@link Direction#DOWN}. Both return the new pane, or empty when the window or pane is gone (or, for a split, its session has ended) or the request names a profile Jasper does not list. A local request needs {@code terminal.open}:

RequestStarts
{@link dev.jasper.sdk.terminal.OpenRequest#local()}The user's shell, where New Tab would start it. A split starts in the target pane's folder.
{@link dev.jasper.sdk.terminal.OpenRequest#localIn(Path)}The user's shell in an absolute folder.
{@link dev.jasper.sdk.terminal.OpenRequest#localProfile(String)}A detected shell profile, such as PowerShell 7 or a WSL distribution.
{@link dev.jasper.sdk.terminal.OpenRequest#local(LocalSpec)} with {@link LocalSpec#running(List,Optional)}A program instead of the shell, with the shell's environment. Each word is passed as it is, with no shell parsing it. Its pane closes when it exits with status 0 and stays open otherwise.
{@link dev.jasper.sdk.terminal.OpenRequest#session(SessionSpec)}A session the plugin provides; needs {@code session.provide}. See below.
 
context.actions().register(ActionSpec.of("dev.example.tool.top", "Show Processes"), invoked ->
    context.terminals().openTab(invoked.window(),
        dev.jasper.sdk.terminal.OpenRequest.local(LocalSpec.running(List.of("top"), Optional.empty()))));

A local request without a profile starts the user's default shell profile, for a split too, where the user's own Split repeats the target pane's profile. A profile id Jasper does not list opens nothing and is logged.

Shell profiles

{@link Terminals#profiles()} lists the shells Jasper detected for local panes, in the order its settings list them, as {@link ShellProfileInfo}s with an id, a name, a {@link ShellProfileInfo.Kind} and a detail. On Windows they are {@code powershell}, {@code pwsh} (when PowerShell 7 is installed), {@code cmd}, {@code cygwin} (Cygwin Bash, when Jasper's own Cygwin is installed) and {@code wsl:} for each WSL distribution; elsewhere {@code login}, the login shell; and last {@code custom}, the user's custom command. Detection can finish after the plugin starts: {@link Terminals#onProfilesChanged(Runnable)} runs after the first detection and after each later one whose result differs. Both need {@code terminal.open}. Remote lists the WSL distributions this way and opens them with {@code localProfile}.

Shell environment

String home = context.dataDirectory().toString();
context.terminals().environment(jasper -> Map.of("DEPLOY_TOOL_HOME", home));

With {@code terminal.environment}, {@link Terminals#environment(Function)} adds variables to each new local shell and to each program a tab or split runs. The contributor runs on the UI thread for every launch, receives Jasper's own environment (read-only) and returns the variables to add, or {@code null} for none; it must not block or do I/O. A shell's environment is Jasper's own, then Jasper's variables, then the contributions, then the user's {@code [terminal.env]}, then {@code TERM} and {@code COLORTERM}, so the user's settings win. A name must match {@code [A-Za-z_][A-Za-z0-9_]*}; {@code TERM}, {@code COLORTERM}, {@code TERM_PROGRAM}, {@code TERM_PROGRAM_VERSION} and names starting {@code JASPER_} are reserved. Invalid names, reserved names and values holding NUL are dropped and logged once; when two plugins set one name, the first by plugin id wins. WSL profiles and provided sessions get no contributions. The Editor sets {@code EDITOR} this way.

Terminal events

Subscribing to any {@link TerminalEvents} topic needs {@code terminal.observe}. Events name windows, tabs and panes by id and arrive later on the UI thread; there is no replay, so read the current state from {@link Terminals} first.

TopicPayloadWhen
{@link TerminalEvents#WINDOW_OPENED}, {@link TerminalEvents#WINDOW_CLOSED}, {@link TerminalEvents#WINDOW_ACTIVATED}{@link TerminalEvents.WindowEvent}A Jasper window, the main window or a child window, opened, closed or became the active one.
{@link TerminalEvents#TAB_OPENED}, {@link TerminalEvents#TAB_CLOSED}, {@link TerminalEvents#TAB_SELECTED}{@link TerminalEvents.TabEvent}An item, terminal or content, opened, closed or became its window's active one.
{@link TerminalEvents#TAB_MOVED}{@link TerminalEvents.TabMoved}An item moved to another window, instead of a close and an open; a moved terminal keeps its pane's id.
{@link TerminalEvents#PANE_OPENED}, {@link TerminalEvents#PANE_CLOSED}, {@link TerminalEvents#PANE_FOCUSED}, {@link TerminalEvents#BELL}{@link TerminalEvents.PaneEvent}A pane opened, closed, got focus or rang its bell.
{@link TerminalEvents#ACTIVE_PANE_CHANGED}{@link TerminalEvents.ActivePaneChanged}{@link Terminals#activePane()} changed; empty when there is none.
{@link TerminalEvents#TITLE_CHANGED}{@link TerminalEvents.TitleChanged}A pane's title changed.
{@link TerminalEvents#CWD_CHANGED}{@link TerminalEvents.CwdChanged}The shell reported a new folder, local or remote.
{@link TerminalEvents#COMMAND_STARTED}, {@link TerminalEvents#COMMAND_FINISHED}{@link TerminalEvents.CommandStarted}, {@link TerminalEvents.CommandFinished}A command started, and finished with its exit status, duration and folder. Shell integration only.
{@link TerminalEvents#SESSION_STATE_CHANGED}{@link TerminalEvents.SessionStateChanged}{@code CONNECTING} at each connect of a provided session, {@code RUNNING} when a session starts, {@code EXITED} when it ends.

Shell History adds each command to its index from {@code COMMAND_FINISHED} as it finishes, beside what it reads from the shells' history files.

Providing a session

A plugin with {@code session.provide} can be a pane's session, as Remote is for SSH. Jasper owns everything a pane needs (the emulator, reading and writing, resizing, the status line while it connects, the Disconnected banner with Reconnect, closing); the plugin connects and hands over two streams. This example opens a TCP console port, such as a serial console server's:

public final class ConsolePlugin implements Plugin {
    @Override public void start(PluginContext context) {
        context.actions().register(ActionSpec.of("dev.example.console.open", "Open Console Port"), invoked ->
            context.terminals().openTab(invoked.window(), dev.jasper.sdk.terminal.OpenRequest.session(
                new SessionSpec("console-1:7001", Optional.of("server"), ExitPolicy.KEEP_OPEN,
                    // Called on the UI thread for the first connect and every Reconnect: hand the work over at once.
                    pending -> context.background().execute(() -> connect(pending, "console-1", 7001))))));
    }

    private static void connect(PendingSession pending, String host, int port) {
        pending.status("Connecting to " + host + "…");
        Socket socket = new Socket();
        Subscription cancel = pending.onCancelled(() -> close(socket));
        try {
            socket.connect(new InetSocketAddress(host, port), 10_000);
            var exited = new CompletableFuture<Integer>();
            // From here on Jasper owns the connection and calls close exactly once.
            pending.attach(new TerminalConnection(socket.getInputStream(), socket.getOutputStream(),
                (columns, rows) -> { }, exited, () -> { close(socket); exited.complete(0); }));
        } catch (IOException failure) {
            pending.fail("Could not reach " + host + ":" + port + ": " + failure.getMessage());
        } finally {
            cancel.close();
        }
    }

    private static void close(Socket socket) {
        try { socket.close(); } catch (IOException ignored) { }
    }
}

The pane appears at once, showing the status text (initially "Connecting…") and Cancel. The {@link SessionSpec}'s connector is called on the UI thread while {@code openTab} runs, and again for every Reconnect or Retry, each time with a fresh {@link PendingSession}; it must not block. The spec's title is the pane's title until the program sets one, its icon (a semantic icon name) is the tab's, and its {@link ExitPolicy} decides what happens when the session ends: {@code KEEP_OPEN} shows how it ended and offers Reconnect, {@code CLOSE} closes the pane's tab. With {@link SessionSpec#withRestore(RestoreState)} the session's tab is saved with Jasper's windows, and the plugin's restorer opens it again; Jasper connects it when its tab is first shown.

  • One outcome per attempt. Exactly one of {@link PendingSession#attach(TerminalConnection)}, {@link PendingSession#fail(String)} and cancellation takes effect; later calls are ignored. Every method is safe from any thread, also after the plugin stopped. {@code fail} shows the message with Retry (or Reconnect after an earlier session and in a pane Jasper restored with its tab); a connector that throws fails the attempt with its message.
  • Cancellation. The user's Cancel, the pane closing, the plugin stopping or Jasper quitting cancels the attempt. {@link PendingSession#onCancelled(Runnable)} handlers run once, on Jasper's cleanup thread, to abort a blocking connect. Cancelling before any session was shown closes the pane, except in a pane Jasper restored with its tab, which shows "Connection cancelled" with Reconnect.
  • Ownership. {@code attach} hands the connection over whatever happens: when the attempt was already cancelled or ended, Jasper closes it at once without reading it. Jasper calls {@code close} exactly once, on its cleanup thread; release everything the session holds there.
  • Threads. {@link TerminalConnection}'s {@code output} is read on the session's reader thread and may block; {@code close} must unblock it. {@code input} and {@code resize} are used only on the session's writer thread, which flushes after every write. Input waits in a 4 MiB queue; a write that does not fit is dropped whole and the pane says "Input dropped: the remote side is not accepting input". Request {@link TerminalConnection#TERM} ({@code xterm-256color}) for a remote pseudo-terminal, and pass {@link PendingSession#columns()} and {@link PendingSession#rows()} as its first size.
  • Ending. When {@code exited} completes, Jasper keeps reading output for up to two seconds, then closes the connection; when the output ends first, it waits up to two seconds for {@code exited}, then closes it. The pane shows "Disconnected (exit N)", "Disconnected: The connection ended: message" when {@code exited} completed exceptionally, or "Disconnected: The connection ended without an exit status" when the output ended without one.
  • Folders. {@link PendingSession#reportRemoteDirectory(RemoteDirectory)} gives the pane a remote folder to show until the shell reports its own; it never becomes a local folder. A remote shell with Jasper's shell integration reports its folder and commands, and they arrive as remote folders and command events.
