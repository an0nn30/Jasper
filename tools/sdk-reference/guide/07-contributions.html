Contributions

Everything a plugin adds to the workstation goes through its {@link PluginContext}. Jasper draws all of it in its own style and the current look, so a contribution looks built in, and removes all of it when the plugin stops. Ids are namespaced: they start with the plugin's id and a dot. Registration needs the UI thread and an open context.

Actions and shortcuts

An action is a command: an id, a title, an optional icon and keywords, and a handler that runs on the UI thread with an {@link ActionContext}, which names the window it was invoked in and the pane it concerns (the pane under a context menu, otherwise the window's focused pane). Registering an action lists it in every window's command palette and in Settings › Keymap under the plugin's name; then place it:

String run = "dev.example.tool.run";
PluginAction action = context.actions().register(ActionSpec.of(run, "Run Deploy Checks")
        .withIcon("play").withKeywords(List.of("deploy", "check")).withDefaultBinding("cmd+alt+d"),
    invoked -> invoked.pane().ifPresent(pane ->
        context.log().log(System.Logger.Level.INFO, "Checks requested for pane " + pane.id())));
context.menus().standard(StandardMenu.TOOLS).add(run);
context.menus().terminalContext().add(run);
context.toolbar().add(ToolbarItem.action(run));
context.rail().add(run);

{@link PluginAction#setEnabled(boolean)} and {@link PluginAction#setTitle(String)} change it everywhere it appears; closing it removes it and every placement. Placements may name only the plugin's own actions.

A default shortcut is written in the configuration syntax ({@code cmd}, {@code ctrl}, {@code alt}, {@code shift} and a key, such as {@code cmd+alt+d}). On macOS it applies as written. On Linux and Windows {@code cmd} means Ctrl+Shift, and a default that names {@code cmd} and {@code shift} also gets Alt: {@code cmd+alt+d} is Cmd+Option+D on macOS and Ctrl+Alt+Shift+D on Linux and Windows. {@link ActionSpec#withDefaultBindings(String,String)} gives a separate Linux and Windows default instead, naming {@code ctrl}, {@code alt} and {@code shift} literally, or {@code null} for none there. The user's {@code [keybindings]} entry for the action's id wins over the default; a default that collides with a shortcut already in use is dropped, and Jasper's log records "Default shortcut '…' is already used by '…'; bind the action under [keybindings] to give it one." See keyboard shortcuts.

{@link ActionSpec#withContext(ShortcutContext)} limits where the shortcut applies:

ContextApplies
{@link ShortcutContext#global()}Anywhere in a terminal window; the default.
{@link ShortcutContext#terminal()}In a terminal pane, including its find bar.
{@link ShortcutContext#content()}In a content tab the plugin opened.
{@link ShortcutContext#panel(String)}Inside one of the plugin's tool windows.
{@link ShortcutContext#window(String)}Inside one of the plugin's windows. The shortcut of an action in this context never runs; the action still runs from the palette and wherever it is placed.

Where focus is, the most specific applicable action runs: a panel, window or content action, then a terminal one, then a global one. A key whose action does not apply there reaches the focused component, such as the shell. So does a disabled action's key, except in a terminal pane, where it does nothing.

Menus

{@link Menus#standard(StandardMenu)} returns a new section at the end of File, Edit, View, Pane, Tab, Tools, Session or Transfer, after a separator. Jasper has no Tools, Session or Transfer items of its own, so those menus show only while a plugin has entries in them: Tools for utility commands, Session for connecting to hosts and working with sessions, Transfer for file browsers, transfers and file servers. {@link Menus#create(String,String)} adds a top-level menu, placed with the other plugins' menus. {@link Menus#terminalContext()} is a section at the end of every pane's right-click menu; an action run from it receives that pane. A section is a {@link PluginMenu}: add actions, separators and submenus, and rebuild it at any time with {@link PluginMenu#clear()}.

Toolbar

{@link ToolbarItem#action(String)} is a button for one action, {@link ToolbarItem#menu(String,String,List)} a button that opens a menu of actions, and {@link ToolbarItem#view(ToolbarViewFactory)} a small group of the plugin's own controls, one view per window. A toolbar view's root is an INLINE {@link Nodes.Stack} of LABEL texts, DROPDOWN, SEARCHABLE or PICKER choices, at most one PRIMARY button, icon-only GHOST buttons (a blank label with an icon and a tooltip, which need SDK 0.18.1), menu buttons and separators; any other tree is refused, and that window shows no view. When the toolbar is too narrow, buttons move into its "More actions" menu and a view hides.

Status bar

StatusItem status = context.statusBar().add(new StatusItemSpec("dev.example.tool.status", Side.RIGHT, 100));
status.setText("Deploys: 3");
status.setTooltip("Run the deploy checks");
status.setAction("dev.example.tool.run");

One handle drives the item in every window. {@link Side#LEFT} items follow the shell and folder, {@link Side#RIGHT} items precede the terminal size and configuration state, and items on a side are ordered by ascending priority. An item with an action is a button; without one it is plain text. {@link StatusBar#addProgress(StatusItemSpec)} adds a progress control that {@link StatusProgress#update(StatusProgressState)} drives, with a fraction or none and up to two actions.

Tool windows and the rail

A registered panel gets a stripe button in every window: its icon, or under the Enterprise look's labelled stripes a label that starts with the icon and reads its title. Its {@link PanelFactory} builds one view per window, on the UI thread, the first time the panel shows there; share the plugin's model between those instances. The {@link PanelSpec}'s anchor and {@link PanelSpec#withSplit()} pick the default slot (Left Top, Left Bottom, Bottom Left, Right Top, Right Bottom or Bottom Right); the user can move it with the header's Options menu, and Jasper remembers where. Unless the spec names a toggle action of the plugin's own ({@link PanelSpec#withToggleActionId(String)}), Jasper registers {@code .toggle}, titled "Toggle title", with no default shortcut, and View › Tool Windows lists it. {@link PanelHost} is one instance's place in one window: {@link PanelHost#show()}, {@link PanelHost#hide()}, {@link PanelHost#setHeader(PanelHeader)} for a detail, a status dot and icon actions in the header. A factory that throws shows "This panel could not be loaded." in that window. Under the Enterprise look, whose tool windows are flush, the toggle action makes the tool window it shows the active one, which takes the keyboard, and activates a showing tool window that is not the active one instead of hiding it; a plugin's own toggle action does this when its handler calls {@link Panels#toggle(String,WindowHandle)} or {@link PanelHost#show()} for its panel, and any other call only shows or hides. {@link Rail#add(String)} adds a plain button for an action, for example one that opens a plugin window.

Windows, dialogs, overlays and popovers

Jasper builds the frame, title bar, icon, menu bar and theme of every surface; the plugin fills it with a view through {@link WindowSurface#setContent(UiView)} and shows it with {@link WindowSurface#show()}.

  • {@link Windows#create(WindowSpec)}: a plugin window. Its bounds are remembered under its id; a singleton id returns the window already open. Jasper keeps running while it is open.
  • {@link Windows#dialog(DialogSpec)}: a dialog over a terminal window, a plugin window, a content tab or an anchor, presented {@link DialogSpec.Presentation#CENTERED}, as an {@link DialogSpec.Presentation#ATTACHED_SHEET} or as an in-window {@link DialogSpec.Presentation#OVERLAY}; the look may place it another way. {@code show} returns after a modal dialog closes.
  • {@link Windows#overlay(OverlaySpec)}: progress content centred inside a terminal window, one per window. Escape and outside clicks do not dismiss it, so give it a Cancel action.
  • {@link Windows#popover(UiAnchor)}: a popup below (or above) a button or picker, from {@link UiView#anchor(String)}; Escape and clicks outside close it.

Content tabs

{@link Windows#openTab(ContentSpec,WindowOwner,UiView)} opens a view as a document tab in the owner's window, beside the terminal tabs, as the Editor does. The {@link ContentSpec}'s key identifies the document: opening a key the plugin already has open selects that tab and returns its handle. Through the {@link ContentTab} the plugin sets the tab's title, detail, icon, unsaved marker and location ({@link ContentTab#setPresentation(ContentPresentation)}), its commands ({@link ContentTab#setCommands(List)}), which its context menu lists and whose shortcuts apply while it is selected, and its status bar items ({@link ContentTab#setStatus(List)}). Commands with the ids {@code find}, {@code find-next}, {@code find-previous}, {@code copy} and {@code paste} answer Jasper's own Find, Find Next, Find Previous, Copy and Paste, and {@code font-bigger}, {@code font-smaller} and {@code font-reset} its Increase, Decrease and Reset Font Size. The user can move the tab to a separate window and back. {@link Windows#onTabsClosing(BiFunction)} decides whether tabs with unsaved work may close.

File choosers and places

{@link Windows#chooseFiles(WindowOwner,String,Optional)}, {@link Windows#chooseDirectory(WindowOwner,String,Optional)} and {@link Windows#chooseSaveFile(WindowOwner,String,Optional)} show Jasper's file chooser for local paths and return absolute, normalised paths, or nothing when the user cancels; saving over an existing file asks first. {@link Windows#choose(FileChoice)} also offers the roots of the file sources the {@link FileChoice} names and returns {@link FileLocation.Local} and {@link FileLocation.Sourced} values. A {@link FileChoice} opens one or several files, saves to one file with a suggested name, or picks a folder; without an initial location the chooser starts where the owner's focused pane is (in a named source's root when that source locates the pane, otherwise in its local folder), else in the home folder. The owner is a live terminal window, a shown window of the plugin's or one of its content tabs. Call them on the UI thread: they pump UI events until the user answers, so recheck what the result depends on. Closing the owner or stopping the plugin cancels them.

With {@code files.source}, {@link FileSources#register(FileSource)} adds places to the chooser, as Remote does with its saved hosts. The source's roots appear under its {@link FileSourceSpec}'s heading in every chooser whose {@link FileChoice} names its id, which starts with the plugin's id and a dot. {@link FileSource#spec()} is read once; {@link FileSource#roots()} lists the {@link FileRoot}s (an id, a label, a detail shown as the tooltip, and whether opening it needs no connection or sign-in first); {@link FileSource#onChanged(Runnable)} tells the chooser that the roots or their connected state changed; {@link FileSource#locate(PaneHandle)} says where a terminal pane is in one of the roots, so a chooser opened from that pane starts there ({@link FileLocation.Sourced#HOME} when only the root is known). These run on the UI thread and do no I/O.

When the user opens a root, Jasper calls {@link FileSource#connect(String,WindowOwner)}. It may ask the user to sign in over the owner it receives: the terminal window the chooser belongs to, or {@code null} when the chooser belongs to something else, such as a plugin window. It returns a stage that completes, on any thread, with a {@link FileBrowser}; when the stage is a {@code CompletableFuture}, Jasper cancels it to abandon the attempt. Jasper owns the browser and closes it once, when the chooser closes. It calls {@link FileBrowser#home()}, {@link FileBrowser#list(String,Consumer)}, {@link FileBrowser#stat(String)}, {@link FileBrowser#read(String,int)} (the start of a file, for the preview) and {@link FileBrowser#mkdir(String)} on the chooser's worker thread, one call at a time and never on the UI thread, so they may block; {@link FileBrowser#abort()} interrupts a call from any thread. Paths are absolute and use {@code /}. A source method that throws shows no roots, locates nothing or fails to connect ("The plugin could not connect.").

Notifications

NotificationGroup deploys = context.notifications().group(
    new GroupSpec("dev.example.tool.deploys", "Deploys", DisplayMode.CARD));
deploys.post(NotificationSpec.of(Severity.WARNING, "Deploy checks failed")
    .withContent("2 of 14 checks failed on staging.")
    .withAction(NotificationAction.of("Show Log",
        () -> context.platform().openInEditor(context.dataDirectory().resolve("deploy.log")))));

A plugin posts in its default group ({@link Notifications#group()}, named after the plugin) or in groups it declares during {@code start}, which the user can set to show cards, sticky cards, history only or nothing in Settings › Appearance & Behavior › Notifications. Text is plain: a title of up to 200 characters, content up to 4,000, and up to eight actions. {@link NotificationGroup#error(String,Throwable)} attaches the failure, which Jasper records as the plugin's incident and offers with Show more…. Plugins cannot see other notifications. See notifications.

Activities and connections

context.background().execute(() -> {
    ActivityHandle activity = context.activities().begin(ActivitySpec.of("Deploy checks"));
    for (int check = 1; check <= 14; check++) activity.progress(check / 14.0, "Check " + check + " of 14");
    activity.succeed("All 14 checks passed");
});

A running activity shows as a card on Desk Buddy, with its fraction and detail. When it succeeds or fails, Jasper posts the outcome in the plugin's {@code .activities} group, so the user can mute outcomes without muting the plugin's other notifications; a cancelled activity posts nothing. {@link ActivitySpec}'s action, one of the plugin's own, runs when the user clicks the card. A connection ({@link Activities#connection(ConnectionSpec)}) has a state instead of an end, up, degraded or down, until the plugin closes it; Desk Buddy shows a card per connection. Both are published on {@link Activities#TOPIC} and {@link Activities#CONNECTIONS}, which any plugin may follow.

Subcommands

A plugin declares each {@code jasper} subcommand in its manifest and answers it while it runs:

[[subcommands]]
name = "deploy-check"
summary = "Run the deploy checks for the current folder"
context.commandLine().handle("deploy-check", call -> {
    call.out("Checking " + call.workingDirectory() + "\n");
    return CompletableFuture.completedFuture(0);
});

{@code jasper deploy-check …} in a shell reaches the running Jasper, which runs the handler on the UI thread with a {@link CommandCall}: the arguments after the name, the caller's working directory, the Jasper window the command ran in, and the caller's standard output and error. The stage's value is the exit code (0 to 255; anything else is 1); a handler that throws, or a stage that fails, prints {@code jasper: failed: } and exits 1. {@link CommandCall#onCancelled(Runnable)} hears Ctrl+C. While no handler is registered, the command prints {@code jasper: is unavailable (the plugin is off)} and exits 1; an unknown name exits 2. A Jasper started with {@code --plugin-dir}, {@code --safe-mode}, {@code --config} or {@code --standalone} answers {@code jasper} only in its own shells, so try a plugin's subcommand from a shell inside the {@code --plugin-dir} Jasper. {@code jasper --help} lists the subcommands of the plugins that were running when Jasper last started without those options. {@link CommandLine#client()} is the path of the {@code jasper} command itself, for a plugin that writes it into another program's settings. See the command line.

The editor role

{@link Platform#editor(FileEditor)} makes the plugin the editor Jasper opens files with: its configuration files, every {@link Platform#openInEditor(Path)} and a Cmd-click (Ctrl-click on Linux and Windows) on a file path in a local terminal pane reach the plugin's {@link FileEditor} first; returning {@code false} hands the file to the desktop. One plugin at a time holds the role: a bundled plugin's registration replaces one that is not bundled; otherwise the first stays and a later one throws. The Editor plugin takes it. Shell variables ({@link Terminals#environment(Function)}) and program tabs ({@link LocalSpec#running(List,Optional)}) are described in Terminals.

Desktop integration

{@link Platform#copy(String)} puts text on the clipboard; {@link Platform#copySecret(String)} also clears it 30 seconds later if it is still there. {@link Platform#browse(URI)} opens an http or https address in the browser, and {@link Platform#openInEditor(Path)} opens a file in the user's editor. Their failures are posted in the plugin's default notification group, never thrown.
