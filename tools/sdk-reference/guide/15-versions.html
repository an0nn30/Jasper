Versions

This reference documents SDK {@sdk.version}. The release jars carry the version in their names ({@code jasper-sdk-{@sdk.version}.jar}) and as their manifests' {@code Implementation-Version}, and {@link JasperSdk#VERSION} holds it in code. That field is a compile-time constant, so a plugin that reads it gets the version it was compiled against, not the version of the Jasper it runs in. The SDK is at 0.x, which carries no compatibility promise. Javadoc {@code @since} tags in the API reference name the SDK version that added a type or member.

The sdk range

Every manifest says which SDK versions the plugin runs on, as a range. Build against SDK {@sdk.version} and declare:

sdk = ">=0.18.0, <0.19"

That admits 0.18.0 and every later 0.18 version, and nothing from 0.19 on. A plugin that uses something only a later 0.18 version has starts its range there: {@link Appearance#presentation()} needs 0.18.2, so Remote, Credential Vault, File Server and the Sample, which read it, declare {@code sdk = ">=0.18.2, <0.19"}, and so does Enterprise, whose kit file gives the Editor's settings a default that an older Jasper refuses. Icon-only GHOST buttons in a toolbar view and the {@code run} and {@code application} icons need 0.18.1. The other bundled plugins declare the range above.

FormMeaning
{@code >=0.18.0}, {@code >0.18.0}, {@code <=0.18.2}, {@code <0.19}, {@code =0.18.0}A comparator and a version of one to three numbers; missing numbers are 0, so {@code <0.19} means {@code <0.19.0}.
{@code >=0.18.0, <0.19}Comparators separated by commas; every one must hold.
{@code ""}An empty range admits every SDK version.

A bare version such as {@code "0.18.0"} is not a range and makes the manifest invalid, and so does a version with a pre-release or build suffix. The {@code version} of a {@code requires} entry uses the same syntax.

How Jasper checks

Jasper compares the range with its own SDK version twice:

  • When a user installs the plugin. Install from Zip… refuses a zip whose range excludes this Jasper's SDK: "Name version needs SDK range; this Jasper has SDK {@sdk.version}". Nothing is installed.
  • At every launch. A plugin whose range excludes the SDK, wherever it was found, does not load. Its status line in the log and its row in Settings › Plugins say Skipped, and the Plugin problems group posts "Name was not started" with the reason, "needs SDK range; this is SDK {@sdk.version}", and Open Plugins. Plugins that require it, other than optionally, are skipped too.

The range is the author's word. When it admits this SDK, loading still refuses a plugin whose classes refer to SDK types or members this SDK no longer has: Jasper posts "Name could not be loaded", naming the class, the missing type or member and the SDK version to rebuild it for. A call to a method this SDK lacks fails when it runs, as a {@code LinkageError}, which Jasper contains and reports like any other failure of the plugin.
