Capabilities

A capability names something a plugin does that the user cannot see in the window, such as reading what a terminal runs or typing into it, or a role only one plugin at a time can take. Adding actions, menu items, tool windows, content tabs, dialogs, status items, notifications, settings and services needs none. A plugin declares its capabilities in {@code plugin.toml}:

capabilities = ["terminal.observe", "terminal.inject", "palette.contribute"]

The names are the constants of {@link Capabilities}; {@link Capabilities#ALL} lists them. An unknown name makes the manifest invalid.

Consent

A plugin the user installed loads only after the user has allowed every capability it declares. The review sheet in Settings › Plugins lists them in the user's words (in the table below), each followed by its name in brackets, with the warning that a plugin is not sandboxed; Allow and Enable records exactly the capabilities shown. A later version that declares a capability the user has not allowed waits for a new review and does not load until then; one that declares the same or fewer keeps the consent. Bundled plugins and the {@code --plugin-dir} plugin need no review.

So the capabilities a running plugin holds are exactly those it declares: {@link PluginInfo#capabilities()} from {@link PluginContext#plugin()} lists them, and a plugin that can do without one checks before it calls:

if (!context.plugin().capabilities().contains(Capabilities.TERMINAL_INJECT)) {
    context.log().log(System.Logger.Level.INFO, "Typing into panes needs terminal.inject");
    return;
}

Finding windows, tabs and panes, focusing and selecting them, and reading an action's window and pane need no capability; what a handle may then do does.

MissingCapabilityException

A gated call by a plugin that does not hold the capability throws {@link MissingCapabilityException} with the message "Plugin id needs the capability capability; declare it in plugin.toml"; {@link MissingCapabilityException#pluginId()} and {@link MissingCapabilityException#capability()} name both. Pane, tab and terminal calls check the capability before anything else, so a missing declaration shows even on a closed pane or from the wrong thread. Thrown inside a callback, it is contained and reported like any other failure.

The audit log

Jasper logs the gated calls marked above on the logger {@code dev.jasper.app.plugins.audit}, at INFO, as "Plugin id used capability: what", for example "Plugin dev.example.tool used terminal.inject: typed 12 bytes into pane …". It records amounts and targets, never content.

Capabilities cover the calls a plugin makes to Jasper. They do not limit what the plugin's own code does with the Java runtime: it can read and write the user's files, open connections and start programs like any program the user runs. The class loader that hides Jasper's internals keeps plugins on the public API; it is not a security boundary either. Declare only what you use: the list is what the user is asked to allow.
