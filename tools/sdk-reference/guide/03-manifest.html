Manifest

Every plugin describes itself in {@code plugin.toml}, a TOML file at the root of exactly one of its jars (in a Gradle build, {@code src/main/resources/plugin.toml}). Jasper reads it at launch, before it loads any of the plugin's classes, and when a user installs the plugin's zip. The file may be at most 64 KiB.

id = "dev.example.tool"
name = "Example Tool"
version = "1.2.0"
entry = "dev.example.tool.ToolPlugin"
sdk = ">=0.23.0, <0.24"
description = "Runs the team's deploy checks from the command palette."
vendor = "Example"
homepage = "https://example.dev/tool"
icon = "dev/example/tool/tool.svg"
icon_hue = "green"
icon_selected_ink = "foreground"
capabilities = ["palette.contribute", "terminal.inject"]
exports = ["dev.example.tool.api"]
requires = [{ id = "dev.jasper.vault", version = ">=0.2", optional = true }]

[[subcommands]]
name = "deploy-check"
summary = "Run the deploy checks for the current folder"

Keys

Only the keys below are allowed; any other top-level key makes the manifest invalid ("Unknown key: key").

KeyTypeRequiredRules
{@code id}stringyesMatches [a-z][a-z0-9_.-]{0,127}; {@code jasper} and ids starting {@code jasper.} are reserved. It namespaces what the plugin adds: action, menu, panel, split item, status item, palette scope, notification group and file source ids start with {@code .}, as do the topics it publishes, and icon names start with {@code :}. Icon names allow no {@code _}, so a plugin that registers icons keeps its id to letters, digits, dots and dashes.
{@code name}stringyesShown everywhere Jasper names the plugin. It must show something: not only spaces, zero-width or bidi characters.
{@code version}stringyesOne to three numeric components, such as {@code 1}, {@code 1.2} or {@code 1.2.0}, without leading zeros, pre-release or build suffixes. Missing components are 0, and {@link PluginInfo#version()} reads the normalised form, {@code 1.2.0}.
{@code entry}stringyesThe fully qualified name of the entry class, in a package. It must be public, have a public no-argument constructor and implement {@link Plugin}.
{@code sdk}stringyesThe SDK versions the plugin runs on, as a range (see Versions). A plugin whose range excludes this Jasper's SDK does not load.
{@code description}stringnoShown on the plugin's Overview tab in Settings › Plugins and matched by its search.
{@code vendor}stringnoShown in the plugin list, its details and the review and install sheets ("From vendor").
{@code capabilities}array of stringsnoEach one of the twelve names in Capabilities; an unknown name makes the manifest invalid. A user-installed plugin loads only after the user allows all of them.
{@code exports}array of stringsnoPackage names ({@code [a-z_][a-z0-9_]*(\.[a-z_][a-z0-9_]*)*}) other plugins may use. Each names exactly one package; a subpackage is exported only when it is listed too. {@code dev.jasper.sdk}, {@code dev.jasper.app}, {@code dev.jasper.terminal}, {@code dev.jasper.buddy}, {@code java}, {@code javax}, {@code jdk} and their subpackages are reserved. See Services.
{@code requires}array of tablesnoOther plugins this one uses; see below.
{@code icon}stringnoThe path of an {@code .svg} or {@code .png} file in the plugin's jars, at most 256 KiB. Another extension is logged and ignored; a missing, empty or larger file shows the generic plugin icon. See plugin icons.
{@code homepage}stringnoAn absolute {@code http} or {@code https} address, shown as "Plugin homepage ↗" on the Details tab. Anything else is logged and ignored.
{@code icon_hue}stringnoThe tile behind the icon: {@code neutral} (the default), {@code blue}, {@code green}, {@code amber} or {@code purple}. A palette scope that names no hue takes it too. Another value is logged and {@code neutral} is used.
{@code icon_selected_ink}stringno{@code authored} (the default) keeps the icon's own colours on a selected row; {@code foreground} draws it in the selected row's text colour. Another value is logged and {@code authored} is used.
{@code subcommands}array of tablesnoThe {@code jasper} subcommands the plugin answers; see below.
{@code presentation}stringnoThe jar path of the plugin's kit file, which makes the plugin a look. It needs the {@code presentation.provide} capability, and that capability needs this key. See looks.
{@code themes}array of stringsnoJar paths of theme files, each named {@code .json} with an id of lowercase letters, digits and dashes; no id twice. See creating themes.
{@code enabled_by_default}booleanno{@code true} unless set. {@code false} keeps a plugin bundled in the application off until the user turns it on, as the Enterprise look is; an installed or {@code --plugin-dir} plugin ignores it.

Jar paths in {@code presentation} and {@code themes} are {@code /}-separated segments of lowercase letters, digits, {@code _}, {@code .} and {@code -}, without {@code .} or {@code ..} segments or a leading {@code /}.

requires

Each entry names another plugin. Write them as an inline array or as {@code [[requires]]} tables:

[[requires]]
id = "dev.example.core"
version = ">=2.1"

[[requires]]
id = "dev.jasper.snippets"
version = ">=0.1"
optional = true
KeyMeaning
{@code id}Required. A valid plugin id other than the plugin's own; no id twice.
{@code version}A range the other plugin's version must be in. Absent or empty admits any version.
{@code optional}A boolean, {@code false} unless set.

A hard requirement ({@code optional} absent or false) must be met for the plugin to load: when the other plugin is missing or outside the range, this one is skipped ("requires id, which is not available" or "requires id range; found version"), and when the other one fails to start or is skipped, so is this one ("requires id, which failed to start"). An optional requirement never keeps the plugin from loading, and its version range is not checked. Either kind makes the other plugin start first and, when it loads, gives this plugin the packages it exports and the services it publishes; either kind counts toward a dependency cycle, which skips every plugin in it.

subcommands

Each {@code [[subcommands]]} table declares one {@code jasper } command, which the plugin answers with {@link CommandLine#handle(String,CommandHandler)}:

KeyRules
{@code name}Required. Matches {@code [a-z][a-z0-9-]*}; {@code help} and {@code version} are reserved; no name twice.
{@code summary}Required. One visible line without tabs, shown by {@code jasper --help}.

When two plugins declare the same name, a plugin that loads wins over one that does not, then a bundled plugin, then the lowest plugin id; a loading plugin that loses gets the notification "A plugin command was not added". See subcommands.

Errors

A manifest that is not valid TOML, lacks a required key, has a key of the wrong type or breaks a rule above is invalid, and the plugin does not load: Jasper posts "A plugin could not be read" in the Plugin problems notification group with the reason after the plugin's folder, for example "Missing required key: entry" or "capabilities names an unknown capability: terminal.read". The same happens when no jar or more than one jar holds a {@code plugin.toml}, when it is larger than 64 KiB, and when a folder in Jasper home's {@code plugins} is not named after the plugin's id. A zip with such a manifest is refused when the user installs it. The values Jasper only logs and ignores ({@code icon}, {@code homepage}, {@code icon_hue}, {@code icon_selected_ink}) never keep a plugin from loading.

Other files in the jar

A {@code settings.toml} at the root of one of the plugin's jars, at most 1 MiB, is the plugin's settings file as it starts out: the first launch that finds the plugin copies it to {@code plugins//.toml} in Jasper home; a later launch never replaces that file. Write it as commented examples of your settings. Without one, the file starts with a one-line header. See Settings.
