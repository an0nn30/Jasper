The first list is Mermaid 11.17.2's npm production dependency tree as of its publication, on 2026-08-25: the packages
its package.json names in dependencies, and theirs in turn, each at the newest version npm had then in the range the
package that requires it names, with that version's licence from npm's metadata. A package that more than one requires
is listed once for each version those ranges gave. That tree over-approximates what the minified file bundles: type-only
packages (listed apart, under the type declarations) and Node-only tooling, such as d3-dsv's command-line dependencies,
are in the tree but not in the file. The tree also misses what @mermaid-js/parser's own dist bundles, which npm's
dependency metadata does not show, so those packages are listed beside it: its devDependencies langium 4.2.1 and
chevrotain ~11.1.2 and what they require, resolved the same way. Where the file itself names a version, in its licence
banners or in a version constant, that version is given: DOMPurify 3.4.12, where npm's newest in ^3.3.3 was 3.4.14, and
cytoscape 3.34.0, where npm's newest in ^3.34.0 was 3.34.1. khroma's npm metadata names no licence; its npm readme says
"MIT © Fabio Spampinato, Andrew Maney". chevrotain and the @chevrotain packages are under the Apache License 2.0, whose
text ends this notice; DOMPurify is under it or the Mozilla Public License 2.0.
